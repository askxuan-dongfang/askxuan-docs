# 知识、记忆与专题计算：配置及验收

更新：2026-09-30。本页实现已随 WeKnora 集成部署。知识库引擎与线上验收以[WeKnora 接入手册](WeKnora知识库管理与Harness接入.md)为准；现场测绘、复杂图片及第三方授权数据仍保持下表边界。

## 能力与入口

| 能力 | 实现与用法 | 当前边界 |
| --- | --- | --- |
| 跨会话记忆 | H5 AI 问事 → 我的记忆；主动添加、确认、编辑、停用、删除及设置检索有效期。Harness 按本次问题调用 `recall_memory` | 不自动收集历史会话，不把记忆当作本次排盘资料。过期只退出检索，仍能查看和删除。历史回答不自动改写 |
| 知识库 | WeKnora v0.8.2：文档上传、文本导入、分块预览、出处维护、审核启停、重解析及删除；智能体按版本绑定库 | 文件 ≤20MB；实际验证 TXT、DOCX 表格、文字 PDF。扫描件、古籍竖排需另外核对；旧片段不自动迁移 |
| 语义检索 | 文档走 WeKnora 混合检索；记忆走 MySQL 私有条目与本地中文 FastEmbed 512 维向量；最多 5 命中 | 未绑定库拒绝检索。新资料未审核不参与检索。已配置引擎失败明确报错。500 条上限仅适用于旧片段/个人条目，不是 WeKnora 全局限制 |
| 户型 | 风水布局专题 → 上传底图 → 视觉模型识别候选多边形或手工点选 → 两点实测长度校准 → 复核确认 | 视觉模型须另配且支持图像。图片不能提供真实朝向和米数；图纸面积、周长是估算，不是现场测绘，不计算重叠房间总面积 |
| 玄空飞星 | 风水布局专题 → 下卦 → 输入已确认的运数 1–9、向首角度 0–360，计算运/山/向星及九宫 | 采用明示的二十四山与阴阳规则，仅下卦。距离山中心至少 4.5° 的兼向/边界拒绝；替星、特殊门派规则、自动断吉凶未实现 |
| 姓名 | 姓名学专题输入姓及完整候选名 → 康熙/现代笔画对照、五格表 | MIT 康熙数据为第三方整理，不代表权威人口库。异体字保留差异；未知字不补造笔画。五格仅支持明确姓氏的常见单双姓、单双名 |
| 重名 / 商标 | 姓名学选择查询类别，部署授权供应商适配器 | 尚无供应商，显示未接通；不伪造全国重名数、实时商标状态或注册保证 |
| 图表 | 报告中的盘面与依据，依底层工具已返回字段生成图表/表格，展开看详细依据 | 本版扩充字段驱动图表，不代表每个术数流派都有完整专业制图。数据缺失则缺项，不生成假盘 |

记忆和知识是 Harness 的只读检索能力，受已发布版本的 `memoryEnabled`、`knowledgeEnabled` 控制，默认关闭；先保存草稿、质量评测、发布及灰度后生效。保存用户资料并不直接修改已发布版本。

## 三个工作区

1. **能力中心**：现有技能、MCP/内置工具绑定及启停；文档知识库维护、来源定位、导入、检索验证。
2. **智能体开发**：名称、指令、模型、输出上限、绑定知识库、知识和记忆开关。
3. **调试与发布**：单项工具调试、质量评测、运行记录、版本与灰度。质量评测使用正式 Harness 和草稿能力开关；记忆按执行评测的管理员身份隔离，不访问其他用户记忆。旧的“Eino 多步验证”仍是单工具诊断，知识召回质量可在知识库检索验证和正式 Harness 评测验证。

权限沿用网关认证；管理知识需 `admin + platform_super`。个人记忆只读取网关认证身份，模型不能指定 owner。工具无身份参数，最多只读检索，无法代用户写记忆。原文进入模型时作为不可信资料处理。

## 知识引用与隐私

知识结果保留片段 ID、原文、来源、页/段定位、版本和 SHA256。报告生成真实检索引用块，点击可展开原文。历史报告保留生成时快照，修改知识不会篡改旧报告。哈希用于比对文本一致性，**不是区块链存证，也不证明文献本身正确**。

个人记忆不写入报告的原始工具证据块；回答仍可能采用相关偏好。删除记忆会物理删除源条目和向量，已经生成的回答、备份按原有留存策略处理。报告正文中的每个自然语言断言尚未做自动逐句引用核验。

## 本地中文嵌入服务

后端目录 `deploy/ai-embedding` 提供独立 Docker Compose。首次启动下载公开模型；模型缓存持久化，不上传业务原文。首次部署应先准备模型下载网络，启动后检查 `/health`。

    cd deploy/ai-embedding
    # 使用服务端环境配置注入私有随机 AI_EMBEDDING_KEY，勿提交密钥
    docker compose up -d --build

AI 服务配置：

    AI_EMBEDDING_URL=http://ai-embedding:9981/v1
    AI_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
    AI_EMBEDDING_KEY=<与嵌入服务一致的私有密钥>

Compose 单独运行只映射本机 `127.0.0.1:9981`，不能直接让另一隔离容器使用 localhost。将 `ai-service` 与 `ai-embedding` 加入同一内部 Docker 网络后使用上面的服务名；宿主机运行 AI 服务则用 `http://127.0.0.1:9981/v1`。不要公开映射嵌入端口。侧车缺省 768MB / 2CPU，是初始约束，正式部署需检查实际峰值和并发时延。

数据库：对 **askxuan_ai** 执行 `scripts/db/20260930_ai_knowledge_memory.sql`。新表为 `ai_reference_scope`、`ai_reference_entry`、`ai_aux_usage_log`，不会自动导入旧会话。专题目录更新还依赖 `20260929_ai_topic_evidence.sql`。先备份并确认目标数据库；迁移脚本不删除业务数据。完整回滚先关闭新能力，再回滚应用，保留数据表供恢复。

视觉识别沿用已有视觉模型、允许图片主机与上传路径；每用户每分钟最多一次，另共享 AI 日配额，用独立辅助调用表记账，避免与聊天 message_id 冲突。图像候选只在用户确认后成为计算输入。

## 重名与商标接口契约

配置项由部署人员维护，管理台不会接收或展示密钥：

- `AI_NAME_DUPLICATE_URL` / `AI_NAME_DUPLICATE_KEY`
- `AI_NAME_TRADEMARK_URL` / `AI_NAME_TRADEMARK_KEY`

服务端 POST JSON：`{"name":"测试姓名","region":"查询地区","class":"商标类别"}`。如配置 KEY，则以 Bearer 传送。供应商适配器必须返回 HTTP 200 和以下字段：

    {
      "name": "测试姓名",
      "source": "已授权数据供应商",
      "scope": "实际覆盖地区或数据库",
      "asOf": "2026-09-30",
      "result": "供应商核验后的结果及限制"
    }

名称必须完全匹配，来源、范围、更新时间与结果必须齐全。8 秒超时，不跟随重定向。接口未接通、失败和格式错误分开呈现，不转换为零匹配。采购供应商后再实现其私有签名/分页到这个内部契约的适配与真实验收。

## 验证与上线界线

已完成 Go 相关包测试及 race 检测、H5/管理台构建；权限拒绝、owner/revision 限制、停用/到期排除、私有字段保护、导入事务与确认、外部查询来源校验、新增八类工具图表字段契约均有测试。

本机真实 FastEmbed 验证：512 维；“早晨安排工作”与“上午处理专注任务”的相似度 0.6175，无关姓名资料 0.2789；未认证接口返回 401。这是合成样例验证，不是完整召回率评测。

Ego Lite 浏览器验证了记忆确认后保存及删除、户型有效/无效 JSON、知识新增/编辑/检索和三个工作区切换。浏览器使用本地合成 API，与后端单元验证分开记录。2026-09-30 已完成生产迁移、发布、WeKnora 文档检索、Harness 问答与管理台线上验收。真实模型户型识别和授权第三方数据仍未验收；本地合成验证不能替代这两项。
