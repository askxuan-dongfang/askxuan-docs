# 问玄东方运营与合作手册

产品版本：**0.0.1**。

产品配置、供给协作、履约交接与试点决策参考 · 2026 年 9 月 13 日

本手册面向平台运营、商城与制作伙伴、寺院与服务提供者、内容及场景伙伴，也供产业与投资伙伴了解合作准备程度。本册按当前产品能力组织协作说明。具体页面操作配合[产品使用手册](产品使用手册.md)阅读；本手册重点回答谁负责、交付什么、如何验收、哪些条件尚需补齐。

文中“当前实现”依据已核对源码和文档；“建议”“试点约定”属于待双方确认的安排。演示账号、模拟订单、界面截图和构建结果不能证明真实客户、营收、复购或投资回报。本手册不披露未经核验的经营数字，也不承诺融资金额、估值、合作名单或上线日期。

## 1. 产品全景与适用入口

问玄东方将文化内容、AI 问事、真人交流、服务预约、文创商品和手串定制放在同一用户入口中。用户可以先浏览、收藏与交流，再根据实际需要预约、选购或创作；订单和历史记录承接后续服务。这个产品组合已经存在，但组合是否提高成交、交付满意度和复购，需要通过试点数据判断。

| 业务区域 | 当前可使用的能力 | 合作方需要准备什么 |
| --- | --- | --- |
| 服务发现与预约 | 寺院、法师资料，服务、日期与时段选择，预约进度及评价 | 可提供的服务、价格、排班容量、响应与变更规则 |
| AI 与内容交流 | 文字/图片问事、模型选择、历史会话、专题报告；图文、视频、关注、评论与私聊 | 授权素材、内容标准、审核人员、咨询响应人及调用预算 |
| 文创商城 | 商品规格、库存、购物车、地址、订单、发货与普通商城售后 | 真实商品资料、规格、供货量、质检、发货与售后承接人 |
| 东方珠作 DIY | 选材、尺寸与珠序编辑、2D/3D、草稿/设计保存、广场、下单和订单进度 | 材料与配件、纹理素材、制作标准、工期、可选服务及异常方案 |
| 积分与活动 | 积分明细、独立积分商城、消耗积分的转盘/奖池、参与与领奖记录 | 独立库存、参与规则、奖品预算、发货能力及客服解释口径 |

信众和法师分别使用 H5 的 `/c`、`/m`，或对应的两个 iOS 应用。平台与商城人员现在共用 `/admin/` 统一运营台，按账号角色开放功能；旧 `/shop/` 只负责跳转。寺院继续使用 `/temple/`。五类业务角色不等于五套独立后台，打开旧商城书签也不会自动获得平台权限。

各端支持浅色、深色与跟随系统。浅色沿用东方珠作的米白、松绿与暖金，深色使用深棕、朱砂与暖金；标题、正文与数字层级已统一，并适配减少动态效果。六种标识表达同一品牌家族及东方珠作子品牌。合作宣传应使用当前授权资产，当前手册图版需标明观察日期与适用范围。iOS 与 H5 保留各自原生交互差异，现有无签名构建证据不代表应用已在 App Store 发布。

## 2. 角色责任与交接依据

以下是合作试点建议采用的责任分工，最终以双方确认的工作单或合同为准。系统权限决定可执行的操作，业务责任决定谁检查结果；两者应同时明确。

| 角色 | 主要责任 | 每次交接应提供的记录 |
| --- | --- | --- |
| 平台负责人 | 确定开放范围、分配权限、安排审核和客服升级、组织验收 | 合作范围表、责任名单、审核结果、问题清单与验收结论 |
| 商城/制作伙伴 | 维护供给、核对订单、制作质检、发货、承接相关售后 | 商品或材料清单、订单号、质检结果、承诺日期、物流及异常处理结果 |
| 寺院运营 | 维护本寺资料与服务，安排容量、确认预约、分配加持任务 | 服务版本、排班、预约号、任务负责人、变更记录 |
| 法师/服务方 | 按预约或任务承接服务，沟通、上传凭证、推进完成状态 | 接单结果、实际执行时间、所需凭证、未完成原因 |
| 内容/场景伙伴 | 提供授权内容与触达场景，协同专题和用户沟通 | 素材授权、内容清单、发布安排、来源标记与反馈汇总 |
| 财务与客服 | 按业务类型核对款项、积分和履约问题，跟踪处理时限 | 对账依据、退款/结算状态、客服工单及关闭原因 |

每笔业务指定一位对外联系人和一位升级负责人。交接使用业务编号、当前状态、已完成步骤、下一步负责人和承诺时间；不交接密码或登录凭据。用户确认收货、后台完成任务、支付成功及实际到账分别记录，不能由某一方口头确认替代全部结果。

## 3. 合作对象与首批交付物

**文创品牌、材料与制作伙伴。** 首批先提供可稳定交付的少量商品或材料，提交名称、规格、成本与供货报价、库存、图片授权、质量标准和工期。DIY 还需说明天然纹理差异、尺寸容差、配件替代规则及返工责任。交付物是可上架资料包、样品确认记录和履约说明；不以大量空商品页代替供给落实。

**寺院及文化服务提供者。** 先形成经确认可上线的业务范围，再提交机构/人员资料、服务目录、排班容量、响应时限和变更处理规则。涉及宗教相关信息、服务或活动的范围，应由责任方完成专项审查并留存书面结论后确定。平台有对应页面和角色，不代表所有具体服务都可以直接开放。

**内容创作者与场景伙伴。** 提交可使用的图文、视频、设计素材及授权范围，说明可否改编、在哪些渠道展示、使用期限和撤回联系人。联合触达需约定来源识别、咨询承接与订单归属。内容浏览、活动报名、积分参与和购买分别说明，不能把页面有访问写成已获得客户。

**产业与投资伙伴。** 可以讨论供给、团队、渠道或阶段资金支持，但先列出所提供资源、投入条件、交付负责人和可验证里程碑。商品自营、交易服务、经营工具收费和联合项目分成都是可讨论的合作方式，尚不能作为已形成收入的证明；收费主体、费率、成本承担和结算条款需单独确认。

## 4. 从配置上架到履约的工作链

### 准备与上架

1. 平台与伙伴确认试点范围、角色权限和客服联系人，区分演示、受控测试与正式运营数据。
2. 商城人员在统一运营台维护商品、规格、价格、库存和体验标识；积分商品单独配置。DIY 材料同时检查规格与渲染素材，可选加持服务另行维护。
3. 寺院维护资料、服务、法师和可预约安排。容量以实际可承接数量配置，设置休息日后仍需另行处理已有预约。
4. 内容提交审核，商品及服务按对应入口上下架。首页活动和广告保存后，还要检查用户实际看到的内容、跳转目标和有效期。
5. 用被授权的角色检查用户展示、后台读取、价格、库存、地址及空状态。体验商品必须明确提示，不能与普通商品混合结算。

### 接单与执行

普通商城按订单核对规格、数量、支付状态和地址，再安排拣货、质检及发货。库存变化或订单状态不符时先查原因，不能靠重复点击推进。材料或商品的新价格影响后续购买，已生成订单按自身成交记录核对，不用现价重新计算历史金额。

DIY 先核对保存的设计和下单时的材料、价格快照；服务端会重新检查材料可用性、库存与价格。待审订单经商城审核，已支付且审核通过后进入制作。选择加持服务时，寺院分配任务，法师按状态接单、执行并提交凭证；商城确认满足发货条件后登记物流。无加持的订单依自身状态完成制作与发货，不人为添加额外服务环节。

预约由用户选择服务、日期和可用时段后提交，寺院/法师按当前状态确认、开始、完成，再由用户评价。日期、时段、费用和选填随喜应在接单前核对。改变个人排班不等于已取消既有预约；沟通变更时应保留预约号和确认记录。

### 发货、收货与异常

发货前核对收货信息、承运方和单号，记录实际交接时间。用户在收到后确认收货，运营核对异常物流和未完成任务。体验单只走模拟物流，不应据此寄出实物。消息发送结果不明、支付处理中或接口超时时，先查询原订单、原消息或参与记录，确认结果后再重试，避免重复业务。

登录凭证确认失效后，产品会清理当前会话并回到对应登录入口；部分端会先尝试恢复有效会话。网络中断、权限不足和登录时输入错误分别处理。重新登录后应先核对刚才的业务结果，不能假设提交必然失败。

## 5. 三类异常处理不能混用

| 业务 | 当前用户入口与处理链 | 运营需要补充确认 |
| --- | --- | --- |
| 普通商城 | 符合状态的订单可申请售后；审核后按要求填写退货物流，再查看收货及退款进度 | 原因、退回地址、是否需退货、审核人、退款结果和解释时限 |
| DIY 定制 | 两端都有订单查看、支付和已发货确认收货；尚无普通商城式完整顾客自助退货流程 | 以 DIY 订单号登记人工问题，确认材料/制作/服务责任及可执行方案，不指引不存在的顾客按钮 |
| 服务预约 | 页面允许时可取消，预约状态与名额相应处理 | 取消不等于自动退款；涉及款项应单独核对支付和后续处理结果 |

后台拒绝待审核 DIY 订单是制作前的订单审核动作，会停止该流程并恢复相关库存；已付款订单进入退款处理。它不能代替用户自助售后，也不能承诺点击后即时到账。已制作、已发货等阶段的问题应按实际状态与双方约定处理，不把任意阶段都描述成可以后台一键拒绝。

试点开始前，应书面确定缺料、尺寸不合、实物与素材差异、制作延期、错发、退回和返工的责任、材料留证方式及响应时限。这是合作交付约定，不表示当前软件已经自动执行全部规则。客服关闭问题前，应保留用户沟通、处理动作和最终结果，不能仅以“已转给商家”视为解决。

## 6. 人民币、积分与体验数据分别运营

当前支付服务使用模拟渠道。模拟支付可以推进普通业务订单和相关记录，但不会证明微信、支付宝或银行真实扣款完成。尤其不能把“所有演示交易都不影响积分和财务”当作通用规则；只有明确的体验订单按其独立规则隔离消费积分和真实营收口径。

| 体系 | 规则与运营口径 |
| --- | --- |
| 普通商城、DIY、预约 | 按各自人民币订单核对金额、支付及履约；当前模拟成功应从真实成交和真实回款统计中排除 |
| 体验商城 | 明示模拟支付、模拟物流，不实际扣款或发货，不奖励消费积分、不记入真实营收；与普通订单分开结算 |
| 消费积分 | 每笔符合条件订单实付满 100 元得 1 积分，零头舍去；199.99 元为 1 分。退款按净实付重算并扣回，余额可能为负 |
| 积分商城 | 用积分兑换确定商品或权益，独立商品、库存和兑换订单；待发货取消和已发货收货按页面状态处理 |
| 积分转盘/奖池 | 每期明示正整数参与积分，每人每期一次；成功参与即扣分，中奖与否均不退分；奖品由平台预算承担 |
| 功德值与随喜 | 功德值属于独立成长语义，不是可提现余额；随喜属于订单中的自愿金额，不存入“功德金钱包” |

转盘即时揭晓，奖池截止后开奖。参与失败不扣分，重复请求不会重复扣分；结果以参与记录为准，动画扇区不代表实际等概率。中奖后的地址、发货、收货另有记录。活动发布后规则、时间、预算与奖品冻结，仅无人参与时可取消，运营不能事后随意改规则。

当前不能把积分活动称作免费抽奖。通用活动介绍页主要展示时间、地点和内容，是否免费以该项说明为准，不自动带有报名或领奖流程。奖品预算、兑换成本、消费积分和功德成长应分别说明，不能用一个“奖励金额”合并展示。

## 7. AI、内容与沟通的运营要求

用户可在 AI 自由聊天中选择平台开放的模型，切换影响下一次提问，不改写已有回答；含图片的会话需要支持图片的模型。专题报告有免费摘要和积分解锁完整解读，报告使用的生成配置与自由聊天的选择并非同一个开关。模型列表可见、连接测试成功和真实回答完成是三个不同结果。

有权限的运营人员在 AI 模型设置中测试连接、核对默认模型、图片模型及开放范围，再保存生效；只读状态不能视为已保存。变更用于新问事和新报告，正在生成的回答不受此次切换影响。每次调整建议留存版本、变更目的、测试结果和回退安排，密钥不进入截图、工单或合作资料。

AI 内容按传统文化交流与参考说明，不承诺预测或现实功效。模型配置不等于每条回答已经人工审核。合作方应明确反馈入口、异常内容处置人、人工复核范围及调用成本承担，正式采用外部内容安全服务还需独立接入和验收。

法师从“工作台 → 内容与直播”发布图文或视频。保存草稿、提交审核、审核通过和公开展示应分别核对。平台审核员需打开真实文字与素材，素材不可预览时先核实；驳回应给出可执行的修改意见。后台“帖子审核”面向大师广场内容，不能当作所有 DIY 公开作品均经过同一发布前审核的保证。

DIY 已有自己的保存、发布/下架和管理状态入口，公开设计继续编辑保存后会转私密，需要重新发布。内容和设计授权应分别约定，平台提供复制入口不意味着任意外部素材已获得授权。

私聊和业务会话支持消息、附件、未读与失败重试。消息已发送表示服务器接受记录，已读依读取记录，不代表服务已经完成。不得将私人问事正文、身份资料或附件直接用作公开案例；合作复盘使用去标识的统计与获得授权的材料。

## 8. 日常运营与问题闭环

建议每日按“供给、待办、履约、例外”四步检查：先看缺货与即将过期的活动，再分派待审订单、预约和内容；随后核对到期制作、待发货、异常物流及未回复咨询；最后确认失败支付、退款处理中和用户投诉是否有人持续跟进。检查频率及响应时限由双方按供给量确定，不在资料中预填无法执行的承诺。

建议每周围绕少量具体问题复盘，例如某材料缺货导致多少次无法下单、制作在哪一阶段超时、用户为何申请售后、哪些内容带来了可归因的有效访问。会议结论落到负责人、改动范围和复查日期；新活动或扩大供给前先关闭影响资金、授权和交付的阻断问题。

数据异常先核对日期、筛选、角色和业务类型。无权限、加载失败和确实没有记录分别处理，不把空白表格写成零成交。试点数据保留环境标记和来源；受控测试记录用于验证功能，正式经营记录用于评价合作效果。

## 9. 运营指标与计算口径

下列是试点建议口径，不代表当前后台已自动提供全部指标。试点前由双方确认统计周期、观察窗口、数据来源、去重方法和负责人；无法从现有记录可靠取得的指标标为“待采集”，不以估算填成实绩。

| 指标 | 建议定义与需要排除的情况 |
| --- | --- |
| 有效访问人数 | 在选定入口完成约定有效行为的去重访问者；先约定跨设备规则，排除机器人与内部测试 |
| DIY 设计完成率 | 观察窗口内成功保存到账号的创作用户数 ÷ 进入编辑器的创作用户数；本地草稿不算完成，恢复旧作品另标 |
| 设计到付费转化 | 同一批保存设计的用户，在约定窗口内产生可关联真实支付 DIY 订单的人数占比；不能混入模拟支付 |
| 真实付费转化 | 可归因的首次真实付费人数 ÷ 同一来源有效访问人数；跨期访问按约定窗口关联 |
| 客单价与净成交额 | 真实支付金额 ÷ 相应支付订单数形成支付客单价；退款另列并计算净成交额，不能把交易总额直接当平台收入 |
| 按时交付率 | 到承诺交付日应完成的订单中，按约定完成交付的比例；尚未完成且逾期的订单计为未按时 |
| 售后与响应 | 售后订单数、原因分布、首次有效响应时长及关闭时长；申请退款和实际退款分开记录 |
| 现金复购率 | 首购人群中，在统一观察期内再次真实付费的人数占比；只纳入已满观察期人群，回访、积分兑换不算现金复购 |
| 渠道获客成本 | 可归属渠道投入 ÷ 该渠道新增真实付费用户数；分母为零时单列投入，标记尚未获得付费用户 |
| AI 与权益成本 | 按实际承担方归集模型调用、积分兑换、奖品、运费及客服成本；积分扣分本身不是现金收入 |

订单贡献用于合作决策参考：自营模式以按约定口径确认的净收入，扣除商品、制作、履约、渠道等直接变动成本；交易服务模式以合同约定的平台服务收入扣除平台承担的成本。退款已冲减收入时不要再次全额作为成本扣减，返工和额外运费则按实际记录。

双方应先确认会计与管理口径、税费及成本承担，再讨论贡献和投入回收。现阶段未形成可用于本手册展示的单位经济性、获客回收期或 ROI 结果。行业增长和竞品数据不能替代问玄东方的经营证据。

## 10. 试点阶段与验收记录

**阶段一：准备可交付场景。** 选定一类商品、一次定制或一项确认可开放的服务，完成资料、样品、责任、库存、授权、客服与外部能力清单。验收输出为试点范围表、已上架清单、操作走查记录和待办。个性化消费、礼赠、文化兴趣人群都可作为招募假设，需用真实访谈和行为验证。

**阶段二：受控验证完整流程。** 用被授权的测试身份走通配置、提交、重复请求、库存不足、角色限制、履约与异常处理。核对浅深主题、移动布局、字体、减少动态效果、登录失效回登录和重新查询原记录。验收输出写清端、环境、版本、步骤、期望、实际结果、业务编号及证据；测试通过只对应被执行的范围。

**阶段三：具备条件后运行真实业务。** 完成真实交易和相关外部服务验收后，再在约定小范围内运行。记录真实款项、履约、售后、成本和用户反馈，按预先约定指标复盘。通过才讨论增加供给、渠道或投入；没有观察到付费与交付证据时，不用注册或曝光量替代结论。

| 正式范围确认项 | 当前边界与放行证据 |
| --- | --- |
| 真实支付、退款与结算 | 当前支付为 mock；真实渠道、回调、重复通知、退款、对账及实际到账需按选定渠道验收，提现申请不等于到账 |
| 短信与物流 | 演示登录、媒体或物流页面存在不等于外部服务全程可用；验证发送接收、实际承运与异常处理 |
| APNs 与原生分发 | 已有设备登记和推送代码，但缺少完整凭据配置与真机通知验收；需实际验证锁屏、点击跳转、退出解绑和签名分发 |
| 公网音视频与直播 | 公网通话当前暂缓；直播有能力检测与开关，生产直播未完成验收，不按默认可用能力对外承诺 |
| 内容与业务范围 | 完成素材授权、专项业务审查、审核人员与反馈机制，分别留存结论 |

验收单结论建议统一为“通过、附条件通过、未通过、未执行”。附条件通过必须列明允许范围、限制、责任人和复查时间。源码存在、构建成功、网站可打开、受控业务通过和真实业务验收分别记录；新版本或合作范围改变后，对受影响内容重新核验。

## 11. 合作讨论时逐项确认

首次会议建议形成一页决策记录：合作目标是什么，首批只做哪些供给，面向哪些人群，在哪些端和渠道开放；双方各投入什么，由谁上架、审核、接单、制作、发货和处理异常；有哪些能力需先完成接入，何时复查。每项写结论、负责人和证据，不把“后续沟通”当作已落实。

商务条款至少明确销售或服务主体、定价权、供货成本、费用与分成、退货返工承担、款项结算周期和数据核对方式。积分兑换、奖品和 AI 调用费用由谁承担应单独列明。团队、资金和渠道资源按实际承诺记录，未经确认的融资规模、估值与目标收入保持空缺。

内容和数据条款应明确素材可用范围、作品复制与再利用、公开案例授权、用户沟通边界，以及合作终止后下架、在途订单和售后的继续承接。试点方案还应约定目标值、停止或缩小范围的条件、问题升级方式及复盘决策人。用这些交付条件讨论合作价值，逐步形成可查证的经营基础。
