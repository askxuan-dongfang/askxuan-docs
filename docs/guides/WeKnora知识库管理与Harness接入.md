# WeKnora 知识库管理与 Harness 接入

更新：2026-09-30。接入基于 WeKnora v0.8.2，官方源码固定 3e8b0bfc80b845b2d4b2ed683994748741450a97。部署验收结果见文末。

## 管理员怎么用

1. 总管理台 → AI 问事工作台 → 能力中心 → 知识库，新建知识库，填写名称和用途。
2. 上传 PDF、DOCX、XLSX、CSV、TXT、Markdown（单份 ≤20MB），或直接添加原文。填写作者、书名、版本等真实出处。
3. 等待解析完成，点击“预览”查看真实原文分块。解析失败可以重解析；重新解析会自动撤销审核状态。
4. 核对内容和使用权限后“审核启用”文档，并在知识库设置中启用知识库。
5. 在“检索验证”输入问题，检查命中的原文和出处。没有命中不等于资料中一定没有，应检查解析、审核、措辞和索引。
6. 智能体开发 → 绑定知识库 → 开启知识检索 → 保存草稿 → 调试与发布中完成质量评测并发布/灰度。只有发布后才影响用户。

库名与用途说明在问玄管理台维护；上游文件、分块、索引由 WeKnora 保存。停用和删除立即影响后续检索，已经生成的报告仍保留当时的引用快照。

## Harness 如何融合

用户问题 → 当前已发布智能体版本 → Eino 工具选择 → `search_knowledge` → 服务端绑定库范围与审核策略 → WeKnora 向量＋关键词混合检索 → 原文片段、出处、分块定位 → 模型生成回答 / 报告引用。

适配器采用 WeKnora REST API；呈现给模型的是现有 Harness 只读工具，不另开 WeKnora 的对话智能体，也不额外安装任意 MCP。现有 taibu MCP 与专题算法照常由 Harness 调用。报告计算依据与文献引用分别保留。

空知识库绑定列表不检索任何资料。模型不能指定库 ID、管理员身份或用户身份；不提供上游管理密钥。每次检索校验库启用状态和文档审核状态，返回前再次检查撤销。

## 哪些内容保存在哪里

- WeKnora PostgreSQL：文档元信息、分块与索引；文件卷：原始文件和解析资源；Redis：任务队列。
- 问玄 MySQL：知识库登记、文档审核策略、管理操作审计；用户记忆仍是本人确认的私有条目。
- FastEmbed：本地中文 `BAAI/bge-small-zh-v1.5`，512 维；不上传原文至外部嵌入 API。
- 报告：生成时引用片段与 SHA256 快照。哈希只比对内容，不证明文献正确。

## 怎么测

使用自有合成资料创建临时库，分别上传文本、带表格的 DOCX 与文字型 PDF。核对解析完成、分块存在；未审核时检索零命中；审核文档且启用库后命中目标段落；停用、重新解析或删除后不再命中。用普通信众/大师/寺院身份访问管理 API 必须拒绝。将库绑定草稿，在 Harness 评测中检查检索工具及引用；在发布后实际问答轨迹中核对工具执行。

上传与解析不收取业务积分；模型生成仍走原有用量管理。不要用客户隐私资料作为公共测试文档。测试结束删除临时库，保留验收记录。

## 当前范围与边界

本轮包含文档管理、混合检索、权限适配、审核与检索验证、智能体知识库绑定及报告引用。WeKnora 自带 Wiki、第三方数据源同步、独立 Agent、联网搜索、沙箱等没有开放。扫描件、古籍竖排与复杂户型图需另测 OCR/视觉能力；不能把本次文字型 PDF 验收推广为所有文档都准确。

旧 MySQL 片段数据保留，未自动迁移。接通 WeKnora 后新管理台使用文档知识库，跨会话记忆仍按用户隔离，不自动收集聊天历史。
