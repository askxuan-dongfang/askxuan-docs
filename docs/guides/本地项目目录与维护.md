# 本地项目目录与维护

更新：2026-09-13。本地工作区 `DongFang/` 本身不是 Git 仓库，不能在根目录用一次 Git 操作代替各仓检查。

当前文档入口见[文档首页](../../README.md)，之前报告见[报告目录](../reports/README.md)。根部 `specs/` 原为空目录，正式规格仍在文档仓 `specs/`；不要重复建一套任务板。

## 同步与隔离

开始前分别检查 Git 状态、HEAD、上游和 worktree。仅对干净且当前提交为上游祖先的日常目录执行 `git merge --ff-only`；存在未提交/未推送内容时保留并单独处理。创建任务副本时记录起始 SHA、嵌套仓库和使用者，不修改另一任务的未提交文件。

旧工作树不能只因已推送便整目录删除：先检索引用它的本地夹具、文档和共享依赖。退休时先处理嵌套 H5，再通过 `git worktree remove` 管理外层；独立 clone 另核对所有分支和未跟踪资产。

## 清理范围与恢复

本轮仅清理经 Git、活跃句柄和可恢复来源核验的旧 `node_modules`、Web `dist`、Vite 缓存及 Xcode 的缓存/中间产物。保留源代码、锁文件、主目录依赖、iOS 日志/调试产品、CI 原始发布包、回执、数据库、备份和配置。精确执行清单在工作区 `artifacts/maintenance-20260913/cleanup-executed.json`，本次总量见[核验报告](../reports/2026-09-13-产品与文档核验.md)。

| 已清理内容 | 恢复 |
| --- | --- |
| 旧副本 Node 依赖 | 在原应用目录执行 `npm ci`；需要可用缓存或 registry |
| Web dist | 在依赖就绪后执行该应用 `npm run build` |
| Vite 预打包 | 按原夹具/开发配置重新启动，保留的源码和配置不变 |
| Xcode 缓存/中间产物 | 按现有 iOS 构建脚本重新构建，保留的 Logs/Products 不代表新构建已完成 |

不要对工作区执行全局 `git clean -fdx`，也不要把 `.local/openim`、整个 `build`、`artifacts` 或数据库备份视为可重建缓存。删除目录的 `du` 占用与 APFS 实际空闲空间变化可能不同，报告明确统计口径。

## 文档核验

从文档仓根目录运行：

```sh
node scripts/audit-markdown-links.mjs
node scripts/audit-api-contracts.mjs ../askXuan-backend
```

第二项覆盖显式和数据驱动业务 HTTP 路由；旧后端扫描器只覆盖部分文件。脚本不能证明字段、权限、真实设备和第三方交易已验收。对规格使用既有 lean-spec 流程，文档更新不自动将未完成实施标为 complete。

发布和回滚按[GitHub Actions 与 ECS](../deployment/GITHUB-ACTIONS.md)执行；本地目录整理不需要重发前后端业务服务。
