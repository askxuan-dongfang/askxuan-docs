# 本地项目目录与维护

产品版本：**0.0.1**。工作区 `DongFang/` 本身不是 Git 仓库，源码在各独立仓库维护。

## 当前目录

| 路径（相对工作区） | 用途 |
| --- | --- |
| `askXuan-backend/` | 后端 main；业务服务、网关、部署脚本及配置 |
| `askXuan-frontend/` | 前端 master；两套 iOS、管理后台与共享视觉 |
| `askXuan-frontend/apps/web-platform-admin/` | 总管理台与全部商城业务；生成旧 `/shop` 静态迁移页 |
| `askXuan-frontend/apps/web-temple-admin/` | 保留的独立寺院管理台 |
| `askXuan-frontend/apps/web-h5/` | H5 独立仓库 main，需单独提交与发布 |
| `askXuan-docs/` | 本仓 master；当前手册、技术/API、部署和需求 |
| `askXuan-frontend/packages/brand/` | 唯一正式品牌母版、生成器与导出资源 |
| `artifacts/history/` | Web / 后端历史验收、截图、日志和资料，按月份与任务归档 |
| `artifacts/releases/` | 后端、Web、H5 当前发布与必要回滚包，按组件与发布 ID 归档 |
| `artifacts/native/` | iOS / macOS 交付包和原生验收，按月份与任务归档 |
| `artifacts/maintenance/` | Git 同步、清理回执和源码恢复归档，按月份与任务归档 |

手册正文、图版、PDF 分别位于本仓 `docs/guides/`、`docs/assets/0.0.1/`、`output/pdf/`。需求从 [specs](../../specs/README.md) 进入，不在工作区另建任务板。AI 专题/MCP 运行依赖按后端当前配置维护，不能将独立产品的品牌或构建默认归入问玄东方。

## 产物归档规则

`artifacts/` 顶层固定为 `history`、`releases`、`native`、`maintenance` 四个目录，以及 `README.md`、`INDEX.md` 两份导航文件。后续任务不能在顶层新建日期目录、日志、压缩包或源码副本。

| 内容 | 路径（相对工作区） |
| --- | --- |
| Web / 后端验收、截图、测试记录、资料出处 | `artifacts/history/YYYY-MM/<task>-YYYYMMDD/` |
| iOS / Mac 安装包、签名记录、原生验收 | `artifacts/native/YYYY-MM/<task>-YYYYMMDD/` |
| Git 同步、清理报告、恢复归档 | `artifacts/maintenance/YYYY-MM/<task>-YYYYMMDD/` |
| 正式发布与回滚包 | `artifacts/releases/<backend\|web\|h5>/<release-id>/` |

同一任务复用已有目录，任务日期与月份保持一致；日期仅出现在分类内部。`history/legacy/` 只保留已迁入的四份旧文件，不接收后续产物。原生包按实际平台标注；发布包记录用途、源码提交、manifest 与校验值。

临时 worktree、依赖、构建与下载使用临时目录或受管理工作区；完成后只归档交付包和必要验收证据。不得把源码副本、`node_modules` 或 `.git` 放回 artifacts。现有原生 App、xcresult、资料原文、恢复 bundles 和必要回滚包按用途保留，不能仅按大小删除。

移动目录时同步更新索引、文档链接和可用恢复路径；旧路径对照统一维护在工作区 `artifacts/history/PATHS.md`。原始日志、manifest、历史盘点 JSON、Git 引用和已归档原稿保留当时记录，使用路径对照定位，不批量改写历史证据。恢复归档中的本地配置只限本机使用，不整体提交到 Git。

本轮原生验收位于 `artifacts/native/2026-10/native-parity-mac-20261015/`，源码核对与清理记录位于 `artifacts/maintenance/2026-10/repo-sync-cleanup-20261015/`。入口从工作区 `artifacts/INDEX.md` 查找。完成任何新增或移动产物的任务时，从本仓运行：

```sh
node scripts/audit-artifacts-layout.mjs
```

也可显式传入另一个本地工作区根目录；该命令只读检查，不移动或删除文件。它检查固定顶层、月份/任务命名、发布分类、legacy 增量和混入的 Git / 依赖副本；不替代包完整性、设备或线上验收。

## 同步与构建

开始工作时分别检查 Git 状态、HEAD、上游及嵌套 H5。只对干净且当前提交为上游祖先的目录执行快进；保留其他任务的未提交改动。任务隔离副本记录使用者、基线和嵌套仓库，结束前核对变更归属。

依赖与构建产物按对应应用的锁文件、脚本重建。H5 和后台在各应用目录安装依赖及构建；iOS 按[原生开发指南](iOS入门指南.md)重新生成产物。不能仅因某个 build 或 node_modules 曾存在，就把它当作当前验证结果。

管理 Web 的安装、类型检查、组件同步与生产构建只面向 `web-platform-admin`、`web-temple-admin` 两个工程。已删除的 `web-shop-admin` 不再作为依赖来源；商城功能在统一后台的 `src/commerce` 维护。统一后台构建同时生成自包含的 `dist/legacy/shop/index.html`，迁移页不引入独立 npm 包、Vue 组件或旧商城 bundle。

检查旧 `/shop` 时，应验证统一后台当前构建生成的迁移页、目标商城路径和已有后台会话；不能复制上次 `web-shop-admin/dist` 充当新产物。寺院工程、嵌套 H5 与两个 iOS 工程保持各自构建边界。

产品版本为 `0.0.1`，源码提交、构建日志和发布来源使用固定 SHA 留证。当前手册与 PDF 按这组源码维护，页面截图保留实际观察日期；版本号不改变原标签，也不替代当前验证范围。

发布配置、数据库、凭据、运行时卷与挂载不是普通缓存。清理前核对实际使用关系，不能对工作区执行全局 `git clean -fdx`。源码、当前手册和必要资源通过各仓库维护；当前核验记录中不混入过期任务路径。
