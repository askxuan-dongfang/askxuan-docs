## 2. 已确定的实施合同

- 五类编码固定，沿用 24 项宗派 / 信俗基线。`traditionCodes[]` 为增量字段，最多 12 项；草稿可空，新建 / 提交 / 批准须至少一项，每项均为同父且启用的 `tradition`。旧 `taoism` 归一 `daoism`，`sect` 仅为宗派补充说明，不推断或回填关系。
- 旧 `submitted` 缺编码时批准明确失败，保留原状态和修订版本；通过现有退回补填再提交。批准 / 新建的实体、关联及现有账户等数据库副作用同事务。
- 更新省略 / `null` 保留原关系；普通文字编辑保留历史停用、未知和跨父关系，冲突主类型改动拒绝。已有关系修改仍限 `platform_super`，不新增归属变更申请。
- 公开 `GET /api/v1/beliefs/directory-tags` 为 `data.list(code,group,beliefCode,name,value,sort,status)`，仅启用项；管理端继续全量。平台寺院 / 大师列表以 `traditionCode` 在 SQL 先筛选、计数，再分页。
- 资料、关联及服务是独立写入边界；资料和服务各自报告结果并保留失败草稿，仅重试失败段。多个接口没有整页原子提交承诺，也未引入新版本冲突协议。
- 数据库仅五条最小 `GRANT`：`auth_user` 读目录、读 / 插关联；`master_user` 读目录、读 / 插 / 删关联；`temple_user` 增补 `master.belief_code` 列读取（原已可读 `code`）。无结构迁移、目录重建、数据回填和历史清理。

上述合同已与源码及本地实证核对；ECS 后端 / 管理 Web 已发布、最小授权已回读，生产只读业务见第 3.3 节；H5 已部署、文件 / API 核验通过，生产 H5 只读功能、CDP 几何和实际桌面图复核完成，见第 3.5 节；生产 applicant 表单全流程未执行。
