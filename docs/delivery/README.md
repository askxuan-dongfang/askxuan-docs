# 问玄东方产品与测试交付包

版本：0.0.1。编制日期：2026-09-16。包含 4 册核心交付、4 册配套手册、执行模板与核心正文。

## 按接收方开始阅读

- 产品侧：先读核心交付《产品交付与上手指南》，安排角色和业务演示，再读《全平台测试与验收手册》。
- 需求侧：先读《需求范围与追踪矩阵》，确认 22 项需求、差异和排除项，再用 66 个场景组织验收签收。
- 投资侧：先读《投资侧产品与验证说明》，查看产品价值、商业假设和验证阶段；再选择使用指南、运营与竞品配套手册。
- 测试侧：先准备版本、环境、账号和夹具，复制执行模板到本轮记录；同用例多端测试另起行，保留实际与证据。

核心 PDF 位于“核心交付”，已有四册 PDF 位于“配套手册”；可填写 CSV 位于“执行模板”；可维护 Markdown 位于“正文”。本包不包含生产账号密码、工程源码、安装包和私密原始日志。

## 如何开展一次验收

1. 产品与需求负责人确认范围、适用端、环境和允许的测试操作。
2. 技术负责人提供匹配版本及私密账号，建立受控寺院、大师、服务、商品、媒体与积分夹具。
3. 测试人员在测试执行记录 CSV 中按端复制行，执行前提、步骤和断言，填写实际、结论及证据。
4. 失败登记缺陷 CSV；阻塞说明缺失条件。修复后记录版本并复验，不覆盖前轮结果。
5. 需求矩阵关联用例结果，按需求册签收模板记录允许范围、限制、确认人和复验日期。

所有新用例初始为“未执行”。交付文件已检查不代表业务已通过。既有本地、浏览器、部署、原生证据及未验收范围在各册明确标注；本次没有重新运行完整业务或检查实时线上状态。

## 重要边界

普通支付仍为模拟渠道；真实收付款、退款、对账、物流和线下履约需按场景验收。信众 iOS 有本地补丁安装记录，完整真机业务待验；APNs 和公网音视频单独验证。回执提供记录、权限与文件完整性，不是区块链或线下事实保证。测试账号数量和模拟订单不作为投资侧经营数据。

## 文件核对与维护

“文件校验.json”记录包内各交付文件 SHA-256；“交付清单.json”记录核心 PDF 页数、源码和哈希。“文档检查.json”记录本次排版和追踪检查，不记录业务通过。

仓库正文在 askXuan-docs/docs/delivery，PDF 在 output/pdf/交付套件，整包在 output/delivery。维护后运行 scripts/build-delivery-kit.py，逐页检查新增 PDF，再更新文档检查并用 --package-only 重打包。不要把账号文件或 artifacts 原始目录复制进分发包。
