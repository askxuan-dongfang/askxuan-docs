# 媒体与直播服务

> **服务端口**: 8100  
> **代码路径**: `services/infrastructure/media-service`

## 职责

- 为图片、视频和音频生成 Provider 上传凭证，并在完成时校验真实对象。
- 保存媒体处理、审核、封面、播放地址和错误状态。
- 接收带独立回调令牌的转码与审核回调；重复回调幂等，省略字段不清空已有结果。
- 管理直播房间、开播/关闭会话、观看地址及 OpenIM 群聊绑定。

## Provider

| 能力 | 本地开发 | 生产配置 |
|------|----------|----------|
| 媒体 | `local_minio`，真实预签名 PUT 与对象校验 | 可替换 VOD Provider |
| 直播 | `disabled` | 后续接入腾讯云直播/TRTC Provider |

`LIVE_ENABLED=false` 为默认值。未同时启用并配置 Provider 时，能力接口返回 `canStart=false`，法师端隐藏开播控件，服务端 `start` 返回 `50320`，不会伪造成功。

MinIO 使用两个地址：`Endpoint` 供 media-service 在容器网络内校验对象（Docker 为 `minio:9000`），`PresignEndpoint` 生成客户端可访问的上传 URL（本地为 `localhost:9000`）。两者必须指向同一对象存储，不能把容器内部主机名返回给 iOS/Web 客户端。

ECS 通过 `MEDIA_MYSQL_DATASOURCE`、`MEDIA_MINIO_ACCESS_KEY`、`MEDIA_MINIO_SECRET_KEY`、`MEDIA_MINIO_PRESIGN_ENDPOINT`、`MEDIA_MINIO_PRESIGN_USE_SSL` 和 `MEDIA_MINIO_PUBLIC_BASE_URL` 注入运行时配置。生产值仅保存在权限 `0600` 的密钥文件；Nginx `/askxuan-media/` 保留原始 Host 和桶路径，以兼容 S3 签名并供 AI 服务按白名单安全取图。

## 数据表

| 表 | 用途 |
|----|------|
| `askxuan_media.media_asset` | 媒体对象、Provider、处理、审核和播放状态 |
| `askxuan_media.live_room` | 房间所有权、法师、OpenIM 群、Provider 会话和生命周期 |

## 安全边界

- 用户 ID、法师 ID由网关注入；请求体同名字段不能覆盖可信身份。
- 完成上传前通过 Provider `Stat` 校验对象真实存在。
- 视频封面必须属于同一用户、类型为图片且状态可用。
- 媒体详情需要登录；所有者可查看处理过程，其他用户只可查看 `ready + approved` 资产。
- 推流地址仅向房主返回；公开列表只返回 `live` 房间。
- Provider 回调使用 `X-Media-Callback-Token` 常量时间比较。

## 验收

执行 `scripts/test-mvp4-media-live-closed-loop.sh`，覆盖凭证、客户端真实 PUT、对象校验、封面、完成、回调鉴权与重放、审核、公开可见性和直播关闭态。`scripts/test-ai-vision-closed-loop.sh` 进一步覆盖登录用户图片上传、公开 HTTPS 回读、AI 视觉请求与成本审计。脚本会拒绝空 `mediaId`、HTTP 失败和不可访问的预签名 URL，不能以空值继续造成假通过。
