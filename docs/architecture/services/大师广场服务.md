# community-service 大师广场服务设计文档

> **服务端口**: 8099  
> **代码路径**: `services/content/community-service`  
> **数据库**: `askxuan_community`

## 1. 职责与边界

community-service 管理大师广场的图文/视频帖子、点赞、关注和评论。媒体文件不复制到社区库，`post_asset` 仅引用 media-service 的 `mediaId`；创建和编辑时必须校验素材属于当前法师账号且状态为 `ready`。

普通用户只有读取、点赞、评论和关注权限。发布入口只属于法师端，帖子审核和评论审核只属于平台端。评论采用先审后显，`pending` 评论不进入 C 端列表，也不计入公开评论数。

## 2. 数据模型

| 表 | 用途 | 关键约束 |
|----|------|----------|
| `post` | 帖子及审核状态 | `post_no` 唯一；公开查询只读 `approved` |
| `post_asset` | 帖子媒体引用 | `(post_no, media_id)` 唯一；图文 1-9 图，视频恰好 1 个视频 |
| `post_like` | 用户点赞 | `(post_no, user_id)` 主键保证幂等 |
| `post_comment` | 评论及审核状态 | C 端只读 `approved` |
| `master_follow` | 用户关注大师 | `(master_id, user_id)` 主键保证幂等 |

## 3. 审核一致性

法师提交帖子或用户提交评论时，同一 MySQL 事务写业务表和 `askxuan_audit.audit_queue`。平台必须调用 community-service 的审核接口；审核接口在一个事务中更新帖子/评论状态、Audit 队列和 `audit_log`，避免通用审核队列已通过但社区内容仍不可见。

评论通过时才原子增加 `post.comment_count`。重复审核、重复点赞和重复取消点赞不得重复改变计数。

## 4. 客户端能力

| 客户端 | 能力 |
|--------|------|
| C 端 iOS | 图文/视频混合瀑布流、图文轮播、竖向视频、详情、点赞、评论、关注 |
| 法师端 iOS | 图文/视频上传、草稿、提交、编辑、重新提交、下架、我的内容 |
| 平台管理台 | 帖子审核、评论审核 |
| 普通用户 | 不提供发布入口 |
