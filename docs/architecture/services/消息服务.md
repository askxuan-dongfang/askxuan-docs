## 1. 服务职责

message-service 负责全平台消息触达，覆盖站内消息 / 推送 / 模板三大能力：

- **站内消息**（C 端）
  - 用户消息列表（按 `userId` + `isRead` 过滤，分页）
  - 单条标记已读
  - 未读数统计
  - 全部已读
  - 删除消息
- **消息模板**（管理台）
  - 模板列表 / 新建 / 更新
  - 5 类模板：`booking` / `system` / `consult` / `income` / `audit`
  - 变量占位符：`{bookingId}` / `{withdrawalId}` / `{result}` 等
- **推送**（管理台）
  - 主动推送：`app_push`（APP 推送）/ `sms`（短信）
  - 推送日志记录：`pending` / `success` / `failed`
- **MQ 消费**：消费 `booking.notify` / `payment.notify` 等事件，按模板生成站内消息
- **OpenIM 集成**（best-effort）：auth-service 登录时同步用户到 OpenIM 并获取 IMToken，随登录响应返回。OpenIM 不可用时 IMToken 为空字符串，不影响核心业务闭环。OpenIM Server 已部署运行（REST 10002 + WS 10001），iOS 端（ios-customer / ios-master）已通过 CocoaPods 集成 `OpenIMSDK ~> 3.8.3` 真实 SDK，使用 imToken 直连 OpenIM WS 10001 长连接收发消息；REST API 保留作为站内信兜底（未集成 SDK 的端可轮询）。

> v1.0 已实现：站内消息 list + 单条已读。
> v1.1 新增：未读数 / 全部已读 / 删除 / 模板 CRUD / 推送。

## 3. 数据表设计

### 3.1 message（站内消息表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT AUTO_INCREMENT | 主键 |
| user_id | VARCHAR(32) | 接收用户 ID |
| title | VARCHAR(64) | 标题 |
| content | VARCHAR(512) | 内容 |
| biz_type | VARCHAR(16) | booking/system/consult/income/audit |
| biz_id | VARCHAR(32) | 关联业务 ID（如预约单号） |
| is_read | TINYINT | 0 未读 / 1 已读 |
| created_at | DATETIME | 创建时间 |

### 3.2 message_template（消息模板表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT AUTO_INCREMENT | 主键 |
| code | VARCHAR(32) | 模板编码（如 `BOOKING_CREATED`） |
| title_template | VARCHAR(64) | 标题模板（含占位符） |
| content_template | VARCHAR(512) | 内容模板（含占位符） |
| variables | VARCHAR(256) | 变量列表 JSON（如 `["bookingId"]`） |
| type | VARCHAR(16) | booking/system/consult/income/audit |
| created_at | DATETIME | 创建时间 |

### 3.3 push_log（推送日志表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT AUTO_INCREMENT | 主键 |
| user_id | VARCHAR(32) | 接收用户 ID |
| push_type | VARCHAR(16) | app_push/sms |
| title | VARCHAR(64) | 推送标题 |
| content | VARCHAR(512) | 推送内容 |
| status | VARCHAR(8) | pending/success/failed |
| biz_type | VARCHAR(16) | 业务类型 |
| biz_id | VARCHAR(32) | 业务 ID |
| created_at | DATETIME | 创建时间 |

## 4. 接口清单

### 4.1 C 端接口（保留原单数前缀 `/api/v1/message`）

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| GET | /list | 消息列表（按 userId + isRead 过滤，分页） | customer |
| PUT | /:id/read | 单条标记已读 | customer |

### 4.2 C 端扩展接口（复数前缀 `/api/v1/messages`）

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| GET | /unread-count | 用户未读消息数 | customer |
| PUT | /read-all | 用户全部已读（返回受影响条数） | customer |
| DELETE | /:id | 删除消息 | customer |

### 4.3 管理台接口（前缀 `/api/v1/admin/messages`）

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| GET | /templates | 模板列表（按 type 过滤，分页） | admin |
| POST | /templates | 新建模板 | admin |
| PUT | /templates/:id | 更新模板 | admin |
| POST | /push | 主动推送（写 push_log + 调推送通道） | admin |

### 4.4 公告接口

**C 端**（前缀 `/api/v1/announcements`）：

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| GET | /list | 公告列表（分页） | customer |

**管理台**（前缀 `/api/v1/admin/announcements`）：

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| GET | /list | 公告列表（分页） | admin |
| POST | /create | 创建公告 | admin |
| PUT | /:id/status | 公告上下架 | admin |

> 共 **13 个路由**：C 端 6 + 管理台 7（含公告管理）。

## 5. 业务逻辑要点

1. **单数 vs 复数前缀**：保留原 `/api/v1/message`（单数）兼容已有调用，新增能力使用 `/api/v1/messages`（复数），网关 `strings.HasPrefix` 均匹配 `/api/v1/message` 路由规则
2. **未读数**：`UnreadCount(userId)` 遍历内存 messages 统计 `IsRead==0` 的条数，未来用 Redis 计数器优化
3. **全部已读**：`MarkAllRead(userId)` 加写锁批量置 `IsRead=1`，返回受影响条数
4. **删除消息**：内存模式下从切片移除，未来改为软删除（`deleted_at` 字段）
5. **模板变量替换**：消费 MQ 事件时按 `code` 查模板，使用 `strings.ReplaceAll` 替换 `{varName}` 占位符
6. **推送异步化**：管理台 `POST /push` 先写 `push_log(status=pending)`，异步调 SMS / APP 推送通道，回调更新为 `success` / `failed`
7. **MQ 消费入口**：消费 `booking.events`（预约状态变更）/ `payment.events`（支付结果）/ `order.events`（订单状态）/ `blessing.events`（加持任务）/ `review.events`（评价）/ `audit.events`（审核）/ `finance.events`（提现）/ `logistics.events`（物流）共 8 个交换机，按 `biz_type` + `biz_id` 查模板生成站内消息
8. **模板预设**：内置 3 个模板：`BOOKING_CREATED` / `BOOKING_CONFIRMED` / `WITHDRAWAL_RESULT`
9. **全部实现**：v1.2 已实现全部 13 个接口（list/read/unread-count/read-all/delete/template CRUD/push/公告），无空实现残留

## 7. 错误码区间

消息服务使用 `common/errorcode.go` 中的统一错误码（范围 40001-50299），不单独定义错误码区间：

| 区间 | 用途 |
|------|------|
| 40001-40099 | 参数校验错误（如 ErrParam） |
| 40401-40499 | 资源不存在（如消息/模板不存在时使用 ErrBookingNotFound 等） |
| 40901-40999 | 业务冲突（如模板编码重复） |
| 50001-50099 | 系统内部错误（ErrSystem=50001 / ErrNotImplemented=50002） |
| 50201-50299 | 第三方服务错误（如推送失败时使用 ErrOssService 等） |
