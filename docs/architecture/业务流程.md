## 1. 预约祈福完整流程（核心业务线 1）

### 1.1 端到端流程图

```mermaid
flowchart TD
    Start([用户打开App]) --> Browse[浏览寺院/法师列表<br/>temple-service/master-service]
    Browse --> Detail[查看寺院/法师详情<br/>temple-service/master-service]
    Detail --> Select[选择服务+日期+时段<br/>booking-service]
    Select --> Pay[支付功德金<br/>payment-service]
    Pay --> CreateOrder[创建预约订单<br/>booking-service: status=pending]
    CreateOrder --> NotifyTemple[MQ通知寺院管理台<br/>message-service]
    CreateOrder --> NotifyMaster[MQ通知法师工作台<br/>message-service]

    NotifyTemple --> TempleConfirm{寺院确认?}
    TempleConfirm -->|确认| StatusConfirmed[status=confirmed<br/>booking-service]
    TempleConfirm -->|拒绝| StatusCancelled1[status=cancelled<br/>触发退款]
    TempleConfirm -->|超时24h| StatusCancelled2[status=cancelled<br/>系统自动取消]

    StatusConfirmed --> NotifyMaster2[MQ通知法师]
    NotifyMaster2 --> MasterStart{法师开始服务}
    MasterStart --> StatusInProgress[status=in_progress<br/>booking-service]
    StatusInProgress --> MasterComplete[法师完成服务]
    MasterComplete --> StatusCompleted[status=completed<br/>booking-service]
    StatusCompleted --> NotifyUser2[MQ通知用户可评价]

    NotifyUser2 --> UserReview{用户评价?}
    UserReview -->|是| SubmitReview[提交评价<br/>review-service]
    UserReview -->|否,超7天| AutoClose[系统自动关闭评价]
    SubmitReview --> StatusReviewed[status=reviewed]
    AutoClose --> StatusReviewed

    StatusReviewed --> Finance[财务结算<br/>finance-service]
    StatusReviewed --> End1([流程结束])

    StatusCancelled1 --> Refund1[退款流程<br/>payment-service]
    StatusCancelled2 --> Refund2[退款流程<br/>payment-service]
    Refund1 --> End2([流程结束])
    Refund2 --> End3([流程结束])
```

### 1.2 时序图

```mermaid
sequenceDiagram
    participant U as C端用户
    participant GW as Gateway
    participant T as temple-service
    participant M as master-service
    participant B as booking-service
    participant P as payment-service
    participant MSG as message-service
    participant F as finance-service

    U->>GW: 浏览寺院列表
    GW->>T: GET /api/v1/temples
    T-->>U: 寺院列表

    U->>GW: 浏览法师列表
    GW->>M: GET /api/v1/masters
    M-->>U: 法师列表

    U->>GW: 创建预约
    GW->>B: POST /api/v1/bookings
    B->>B: status=pending
    B-->>U: 预约单号

    U->>GW: 支付功德金
    GW->>P: POST /api/v1/payments
    P-->>U: 支付成功
    P->>MSG: MQ: payment.events(通知消息服务)
    P->>F: MQ: payment.events(触发结算)

    B->>MSG: MQ: booking.notify(通知寺院)
    B->>MSG: MQ: booking.notify(通知法师)

    Note over B: 寺院管理员确认
    B->>B: status=confirmed
    B->>MSG: MQ: booking.status(通知法师+用户)

    Note over B: 法师开始服务
    B->>B: status=in_progress
    B->>MSG: MQ: booking.status(通知用户)

    Note over B: 法师完成服务
    B->>B: status=completed
    B->>MSG: MQ: booking.status(通知用户可评价)

    U->>GW: 提交评价
    GW->>B: POST /api/v1/bookings/:id/review
    B->>B: status=reviewed
    B->>MSG: MQ: review.notify(通知寺院)
    B->>F: MQ: booking.status(触发结算)
```

## 2. DIY 手串完整流程（核心业务线 2）

### 2.1 端到端流程图

```mermaid
flowchart TD
    Start([用户打开DIY页面]) --> Browse[浏览设计广场<br/>diy-service]
    Browse --> Design[自主设计手串<br/>选材料/配饰/佛头]
    Design --> Preview[实时预览+价格计算<br/>diy-service]
    Preview --> Reprice[提交订单<br/>服务端锁定材料/SKU并重定价]
    Reprice -->|下架/库存不足| Design
    Reprice --> Snapshot[同事务保存订单/明细/库存扣减<br/>设计与计价快照]
    Snapshot --> ChooseBlessing{选择加持服务?}
    Snapshot -->|商城审核驳回| ReleaseStock[订单取消<br/>同事务归还材料/SKU库存]
    ChooseBlessing -->|是| SelectBlessing[选4项加持之一<br/>灵隐/白云/少林/大昭寺]
    ChooseBlessing -->|否| SkipBlessing[跳过加持]

    SelectBlessing --> Pay[支付<br/>校验订单所属与最终金额]
    SkipBlessing --> Pay
    Pay --> CreateOrder[支付成功<br/>订单仍为pending_review<br/>生成待结算作者收益]
    CreateOrder --> NotifyShop[MQ通知商城管理台]

    NotifyShop --> ShopReview{商城审核设计}
    ShopReview -->|通过| StatusMaking[status=in_making<br/>商城开始制作]
    ShopReview -->|不通过| StatusCancelled1[status=cancelled<br/>退款]

    StatusMaking --> MakingDone{制作完成}
    MakingDone -->|含加持| BlessingBranch[进入加持分支]
    MakingDone -->|无加持| StatusAwaitingShip1[status=awaiting_shipment]

    BlessingBranch --> StatusAwaitingBlessing[status=awaiting_blessing<br/>发MQ派单到寺院]
    StatusAwaitingBlessing --> TempleReceive[寺院管理台接收加持任务<br/>temple-service]
    TempleReceive --> AssignMaster[寺院分配法师<br/>发MQ到法师工作台]
    AssignMaster --> MasterAccept[法师接受任务<br/>master-service]
    MasterAccept --> StatusBlessingProgress[status=blessing_in_progress]
    StatusBlessingProgress --> MasterBlessing[法师执行加持仪式]
    MasterBlessing --> UploadProof[上传凭证照片/视频<br/>file-service]
    UploadProof --> StatusBlessingDone[status=blessing_completed<br/>发MQ通知商城+用户]
    StatusBlessingDone --> StatusAwaitingShip2[status=awaiting_shipment]

    StatusAwaitingShip1 --> Ship[商城发货<br/>填物流单号]
    StatusAwaitingShip2 --> Ship
    Ship --> StatusShipped[status=shipped<br/>发MQ通知用户]
    StatusShipped --> Logistics[物流追踪<br/>logistics-service]
    Logistics --> UserReceive{用户收货}
    UserReceive -->|确认| StatusCompleted1[status=completed]
    UserReceive -->|超7天| StatusCompleted2[status=completed<br/>系统自动收货]

    StatusCompleted1 --> Finance[财务结算<br/>材料费归商城+加持费归寺院/法师]
    StatusCompleted2 --> Finance
    Finance --> End1([流程结束])

    StatusCancelled1 --> Refund[退款]
    Refund --> End2([流程结束])
```

## 4. 寺院/法师入驻、上架与账号分配流程（主数据线）

### 4.1 端到端流程图

```mermaid
flowchart TD
    Start([平台创建寺院或接收入驻申请]) --> TempleDraft[寺院资料录入<br/>temple.status=待审核]
    TempleDraft --> TempleAudit{平台审核寺院}
    TempleAudit -->|驳回| TempleRejected[退回修改/停止入驻]
    TempleAudit -->|通过| TempleNormal[temple.status=正常]
    TempleNormal --> TempleAccount[创建寺院管理员账号<br/>role=temple_admin + temple_id]
    TempleAccount --> TempleAdminLogin[寺院管理台登录<br/>JWT写入templeId]
    TempleAdminLogin --> TempleConfigure[维护寺院信息/服务/法师]

    TempleConfigure --> ServiceShelf[上架寺院服务<br/>temple_service.status=on_shelf]
    TempleConfigure --> MasterCreate[创建法师<br/>master.temple_code=当前寺院]
    MasterCreate --> MasterAudit{平台审核法师}
    MasterAudit -->|驳回| MasterRejected[退回修改/不可上架]
    MasterAudit -->|通过| MasterVerified[auth_status=已认证]
    MasterVerified --> MasterAccount[创建大师App账号<br/>role=master + master_id]
    MasterAccount --> MasterShelf[法师上架<br/>shelf_status=on_shelf]

    TempleNormal --> CustomerTempleVisible[C端寺院可见]
    ServiceShelf --> CustomerServiceFilter[C端找寺院服务筛选可用]
    MasterShelf --> CustomerMasterVisible[C端找师傅可见]
    MasterAccount --> MasterAppLogin[大师App登录<br/>JWT写入masterId+templeId]
```

### 4.2 权责边界

| 动作 | 执行端 | 关键约束 |
|------|--------|----------|
| 创建/审核/封禁寺院 | 平台管理台 | 寺院是平台主数据；仅正常状态进入 C端 |
| 创建寺院管理员账号 | 平台管理台 | 账号角色为 `temple_admin`，必须绑定 `temple_id` |
| 维护寺院资料和服务 | 寺院管理台 | 只能操作 JWT 中 `templeId` 对应的寺院 |
| 创建法师 | 寺院管理台 | `master.temple_code` 固定为当前寺院，不允许创建无寺院法师 |
| 审核/封禁法师 | 平台管理台 | 法师审核通过后才能上架 |
| 创建大师 App 账号 | 平台管理台 | 账号角色为 `master`，必须绑定 `master_id`；系统校验该法师所属寺院 |
| C端展示寺院 | C端 App | 只读取后端 `/temples` 的正常寺院和 `serviceTags` |
| C端展示法师 | C端 App | 只读取已认证、已上架、未封禁法师 |

### 4.3 账号登录上下文

管理账号登录成功后，auth-service 根据角色把绑定对象写入 JWT：

| 角色 | JWT上下文 | 使用方 |
|------|-----------|--------|
| `platform_super` | 平台角色 | 平台管理台 |
| `temple_admin` | `templeId` | 寺院管理台、寺院服务、预约服务 |
| `master` | `masterId` + 所属 `templeId` | 大师 App、法师工作台、加持任务、预约服务 |
| `shop_admin` | `shopId` | 商城管理台 |

任何管理端都不得通过前端传参切换管理对象；后端必须以 JWT 中的绑定对象作为数据权限边界。

## 5. 寺院入驻审核流程（业务线 4）

```mermaid
flowchart TD
    Start([寺院提交入驻申请]) --> Submit[填写信息+上传资质<br/>temple-service]
    Submit --> StatusPending[审核状态: pending<br/>temple_audit表]
    StatusPending --> PlatformReview[平台管理台审核<br/>audit-service]

    PlatformReview --> FirstReview{初审}
    FirstReview -->|通过| StatusFirstPass[status=first_pass<br/>材料完整]
    FirstReview -->|驳回| StatusRejected1[status=rejected]
    StatusRejected1 --> Modify[修改后重新提交]
    Modify --> StatusPending

    StatusFirstPass --> FinalReview{终审}
    FinalReview -->|通过| StatusFinalPass[status=final_pass<br/>寺院上线]
    FinalReview -->|驳回| StatusRejected2[status=rejected]

    StatusFinalPass --> Notify[MQ通知寺院管理员<br/>账号激活]
    Notify --> End([流程结束])
```

## 7. 财务结算流程（业务线 6）

### 7.1 预约订单结算

```mermaid
flowchart TD
    Start([预约订单完成]) --> Calc[计算结算金额<br/>finance-service]
    Calc --> Split{分账}
    Split -->|平台抽成15%| Platform[平台收入<br/>commission_config]
    Split -->|寺院分成85%| Temple[寺院收入<br/>settlement表]
    Split -->|法师分成| Master[法师收入<br/>settlement表]

    Temple --> Monthly[月结周期<br/>每月1号]
    Master --> Monthly
    Monthly --> Withdrawal[寺院/法师申请提现<br/>finance-service]
    Withdrawal --> WithdrawalReview[平台审核<br/>status=pending→approved]
    WithdrawalReview --> Process[财务打款<br/>status=processing]
    Process --> Result{打款结果}
    Result -->|成功| Success[status=success]
    Result -->|失败| Failed[status=failed<br/>重新打款]
    Success --> End([流程结束])
```

flowchart TD

## 8. AI 问事流程（业务线 7）

```mermaid
flowchart TD
    Start([进入 AI 问事]) --> History[加载本人历史会话<br/>MySQL 持久化]
    History --> Input[直接输入问题<br/>默认 general]
    Input --> Session{已有活跃会话?}
    Session -->|否| Create[创建会话<br/>skillCode 可选]
    Session -->|是| Save
    Create --> Save[事务写入 user 消息<br/>和 pending assistant 消息]
    Save --> Provider[异步调用模型 Provider]
    Provider --> Result{调用成功?}
    Result -->|是| Done[assistant 状态 completed]
    Result -->|否| Failed[assistant 状态 failed<br/>显示错误与重试]
    Failed -->|用户重试| Provider
    Done --> Poll[C 端轮询并展示结果]
    Poll --> Input
```
