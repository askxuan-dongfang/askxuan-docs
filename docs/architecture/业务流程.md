## 1. 预约祈福完整流程（核心业务线 1）

### 1.1 端到端流程图

```mermaid
flowchart TD
    Start([用户打开App]) --> Browse[浏览寺院/法师列表<br/>temple-service/master-service]
    Browse --> Detail[查看寺院/法师详情<br/>temple-service/master-service]
	Detail --> Select[读取寺院服务+日期容量时段<br/>temple-service/booking-service]
	Select --> CreateOrder[服务端计价并原子占位<br/>booking-service: pending_payment]
	CreateOrder --> Pay[booking-service 通过 payment gRPC<br/>本地 mock 自动成功]
	Pay --> Paid[支付成功<br/>status=pending]
	Paid --> NotifyTemple[MQ通知寺院管理台<br/>message-service]
	Paid --> NotifyMaster[MQ通知法师工作台<br/>message-service]

    NotifyTemple --> TempleConfirm{寺院确认?}
    TempleConfirm -->|确认| StatusConfirmed[status=confirmed<br/>booking-service]
    TempleConfirm -->|拒绝| StatusCancelled1[status=cancelled<br/>触发退款]
    TempleConfirm -->|超时24h| StatusCancelled2[status=cancelled<br/>系统自动取消]

    StatusConfirmed --> NotifyMaster2[MQ通知法师]
    NotifyMaster2 --> MasterStart{法师开始服务}
    MasterStart --> StatusInProgress[status=in_progress<br/>booking-service]
    StatusInProgress --> MasterComplete[法师完成服务]
```

## 4. 寺院/法师入驻、上架与账号分配流程（主数据线）

### 4.1 端到端流程图

```mermaid
flowchart TD
    Start([平台创建寺院或接收入驻申请]) --> TempleDraft[寺院资料录入<br/>temple.status=待审核]
    TempleDraft --> TempleAudit{平台审核寺院}
    TempleAudit -->|驳回| TempleRejected[退回修改/停止入驻]
    TempleAudit -->|通过| TempleNormal[temple.status=正常]
    TempleNormal --> TempleAccount[创建寺院管理员账号<br/>role=temple_admin + temple_id]
    TempleAccount --> TempleAdminLogin[寺院管理台登录<br/>JWT写入templeId]
    TempleAdminLogin --> TempleConfigure[维护寺院信息/服务/法师]

    TempleConfigure --> ServiceShelf[上架寺院服务<br/>temple_service.status=on_shelf]
    TempleConfigure --> MasterCreate[创建法师<br/>master.temple_code=当前寺院]
    MasterCreate --> MasterAudit{平台审核法师}
    MasterAudit -->|驳回| MasterRejected[退回修改/不可上架]
    MasterAudit -->|通过| MasterVerified[auth_status=已认证]
    MasterVerified --> MasterAccount[创建大师App账号<br/>role=master + master_id]
    MasterAccount --> MasterShelf[法师上架<br/>shelf_status=on_shelf]

    TempleNormal --> CustomerTempleVisible[C端寺院可见]
    ServiceShelf --> CustomerServiceFilter[C端找寺院服务筛选可用]
    MasterShelf --> CustomerMasterVisible[C端找师傅可见]
    MasterAccount --> MasterAppLogin[大师App登录<br/>JWT写入masterId+templeId]
```

### 4.2 权责边界

| 动作 | 执行端 | 关键约束 |
|------|--------|----------|
| 创建/审核/封禁寺院 | 平台管理台 | 寺院是平台主数据；仅正常状态进入 C端 |
| 创建寺院管理员账号 | 平台管理台 | 账号角色为 `temple_admin`，必须绑定 `temple_id` |
| 维护寺院资料和服务 | 寺院管理台 | 只能操作 JWT 中 `templeId` 对应的寺院 |
| 创建法师 | 寺院管理台 | `master.temple_code` 固定为当前寺院，不允许创建无寺院法师 |
| 审核/封禁法师 | 平台管理台 | 法师审核通过后才能上架 |
| 创建大师 App 账号 | 平台管理台 | 账号角色为 `master`，必须绑定 `master_id`；系统校验该法师所属寺院 |
| C端展示寺院 | C端 App | 只读取后端 `/temples` 的正常寺院和 `serviceTags` |
| C端展示法师 | C端 App | 只读取已认证、已上架、未封禁法师 |

### 4.3 账号登录上下文

管理账号登录成功后，auth-service 根据角色把绑定对象写入 JWT：

| 角色 | JWT上下文 | 使用方 |
|------|-----------|--------|
| `platform_super` | 平台角色 | 平台管理台 |
| `temple_admin` | `templeId` | 寺院管理台、寺院服务、预约服务 |
| `master` | `masterId` + 所属 `templeId` | 大师 App、法师工作台、加持任务、预约服务 |
| `shop_admin` | `shopId` | 商城管理台 |

任何管理端都不得通过前端传参切换管理对象；后端必须以 JWT 中的绑定对象作为数据权限边界。

## 7. 财务结算流程（业务线 6）

### 7.1 预约订单结算

```mermaid
flowchart TD
    Pay([模拟/真实支付成功]) --> Receipt[全额进入平台总账<br/>借: platform_cash<br/>贷: customer_funds_held]
    Receipt --> Hold[平台托管<br/>大师端不直接记收入]
    Hold --> Fulfilled[预约履约完成并评价 reviewed]
    Fulfilled --> Calc[读取不可变价格快照<br/>与 commission_config]
    Calc --> Split{平台统一分账}
    Split --> Platform[平台抽成<br/>platform_commission]
    Split --> Temple[功德金扣抽成后<br/>temple_payable + settlement]
    Split --> Master[服务费扣抽成后<br/>master_payable + settlement]

    Platform --> Balance[借贷合计必须等于付款总额]
    Temple --> Balance
    Master --> Balance
    Balance --> Confirm[平台确认结算<br/>pending → confirmed]
    Confirm --> Withdrawal[寺院/法师申请提现<br/>finance-service]
    Withdrawal --> WithdrawalReview[平台审核<br/>status=pending→approved]
    WithdrawalReview --> Process[财务打款<br/>status=processing]
    Process --> Result{打款结果}
    Result -->|成功| Success[status=success]
    Result -->|失败| Failed[status=failed<br/>重新打款]
    Success --> End([流程结束])
```

## 9. 短视频与直播流程（业务线 8）

```mermaid
flowchart TD
    Pick[法师选择封面和视频] --> Credential[media-service 生成上传凭证]
    Credential --> Upload[客户端直传 Provider]
    Upload --> Complete[服务端 Stat 校验并完成]
    Complete --> Process[转码与审核回调]
    Process --> Player[C端按 mediaId 查询并使用 AVPlayer]

    Capability[法师端读取直播能力] --> Enabled{canStart?}
    Enabled -->|否| Hidden[隐藏开播入口]
    Enabled -->|是| Room[创建房间并绑定 OpenIM 群]
    Room --> Start[Provider 返回真实推流和观看地址]
    Start --> Viewer[C端 AVPlayer + OpenIM 群聊]
```

媒体与直播通过可替换 Provider 隔离。首版本地媒体使用 MinIO；生产直播默认关闭，在云账号、密钥、回调域名和 Provider 均配置完成前不展示开播入口。

```mermaid
    Draft --> Submit[提交帖子审核]
    Submit --> Audit[平台社区审核]
    Audit -->|驳回| Edit[法师查看原因并编辑]
    Edit --> Submit
    Audit -->|通过| Feed[C端混合瀑布流/图文轮播/竖向视频]
    Feed --> Like[幂等点赞与关注]
    Feed --> Comment[用户提交评论 pending]
    Comment --> CommentAudit[平台评论审核]
    CommentAudit -->|通过| Visible[评论公开并增加计数]
    CommentAudit -->|驳回| Hidden[保持不可见]
```

帖子与评论审核由 community-service 作为业务状态的唯一写入口，同时写入 Audit Service 队列和日志。平台管理台不得绕过社区审核接口直接改变通用队列状态。
