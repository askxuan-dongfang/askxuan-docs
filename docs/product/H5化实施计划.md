# 问玄东方双端 H5 实施计划

> 起草日期：2026-08-15
> 定位（2026-08-15 已确认）：H5 为**内部员工/客户演示的临时渠道**，iOS 双端**长期保留维护**（仍是正式交付形态），技术栈 React
> 目标：与两个 iOS 端功能等价，URL 交付、改完即发，双轨并行运行
> 依据：功能对齐矩阵.md、PROJECT-ANALYSIS-2026-08-15.md、双端 iOS 源码核查（35 + 15 视图文件）

## 持续对齐约束

- H5 作为独立产品工程和独立仓库管理，不与 iOS 共享 UI 实现，但共享同一后端业务契约。
- 每次 C 端 iOS 或法师端 iOS 新增、修改产品功能时，同一交付批次必须同步 H5 页面、状态、鉴权、API 契约和错误处理。
- H5 验收不以“页面可打开”为标准，而以可部署、可登录、可完成主业务闭环、可产品演示的 MVP 为标准。
- iOS 与 H5 可因平台交互差异采用不同布局，但功能范围、数据来源、计价、支付、状态机和权限规则必须一致。

## 1. 背景与决策依据

iOS 内部分发受限（TestFlight 内测 100 人/构建 90 天过期、Ad-hoc 需登记 UDID 年上限 100 台、企业证书政策风险、交付客户需 App Store 审核），无法支撑"给内部人员试用 + 给客户演示 + 高频更新"的诉求。H5 以 URL 交付、改完即发、刷新即生效，同时覆盖 iOS/Android/PC 与微信内置浏览器。

源码核查确认 H5 可 100% 等价：

| 核查项 | 结论 |
|---|---|
| 原生依赖 | 两端仅 OpenIMSDK 3.8.3 一项；无微信/支付宝 SDK、无推送 SDK |
| 系统权限 | 两端 Info.plist 无相机/定位/推送/后台/麦克风/蓝牙任何权限键 |
| 支付 | channel:"mock" 模拟支付；真实微信/支付宝未接入（对齐矩阵 §5 已列） |
| 实时消息 | 站内消息走 HTTP 轮询（WebSocketManager.swift 注释：后端暂无 WS）；聊天走 OpenIM |
| 视频/直播 | AVPlayer(url) 播放 media-service URL；生产直播默认关闭 |
| 图片上传 | 法师端 PhotosPicker（素材上传）；H5 用 file input 等价 |
| 业务层 | 全部能力 = 292 个 HTTP 契约（API-REFERENCE.md）+ 文件上传 + 视频播放 |
| 通话记录 | C 端 ChatView.swift:40 硬编码 mock 数组，无真实 RTC |

## 2. 技术选型

**推荐方案 A：新建 apps/web-h5/（Vite + React 18 + TS）**

- 单代码库、两棵路由：信众端 /c/*、法师端 /m/*，共享 packages/design-tokens、API 类型、通用组件
- 状态：zustand（与 Expo mobile-customer 同款）；路由：react-router-dom；请求：axios
- 选 React 理由：与 Expo 备用端同栈，API 封装/类型/store 可直接迁移复用；三个 Vue 管理台是独立应用，互不影响
- OpenIM：官方 Web SDK `@openim/wasm-client-sdk`（WASM），连接同一 OpenIM 服务端，按需懒加载
- 认证：localStorage 存 JWT（与 iOS 逻辑完全一致，token/OpenIM userID 体系双轨兼容）；因 H5 为临时演示渠道，**不做** Cookie 化改造
- PWA：仅加 manifest（可选"添加到主屏幕"）；Web Push **不做**（临时定位，站内消息轮询保底）

**备选 B：扩展 Expo mobile-customer 的 web 输出** —— 现仅覆盖 C 端约一半（缺 DIY、大师广场、7 类法事服务页、法师端全部），metro web 打包体积与调试体验不如 Vite。保留其"契约回归"定位，不作为正式 H5。

**备选 C：法师端用 Vue 3（与管理台同栈）** —— 若团队 Vue 熟练度更高可考虑，代价是两套框架、共享层重复建设。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OpenIM wasm SDK 与 3.8 服务端兼容性、WASM 体积（数 MB）、弱网 | 聊天不可用 | M0 优先验证；按需懒加载；兜底：站内消息 HTTP 轮询已可用 |
| 微信内置浏览器（WKWebView）限制 | iOS 用户常从微信打开 | 测试矩阵纳入；必要时引导"在系统浏览器打开" |
| localStorage 存 JWT 安全降级 | 令牌泄露面增大 | **接受**（与 iOS 行为一致、仅内部/演示用途，不做 Cookie 化） |
| 生产支付（微信 H5/支付宝手机网站） | 跳转体验低于原生 SDK | 现状 mock 无影响；接真实支付时按 H5 渠道方案设计 |
| 视频 HLS | 桌面/Android 浏览器不原生支持 | Safari 原生；其余 hls.js |
| DIY Canvas 低端机性能 | 编辑卡顿 | 降低渲染精度、分层缓存、真机性能测试 |
| Web Push 仅部分浏览器支持 | 无系统级通知 | **不做**；站内消息轮询保底，演示场景可接受 |

## 6. 交付与部署

- 内部 URL：dev / staging 两套即可，nginx 静态部署，内网或白名单域名，**不涉及备案与生产合规**
- 网关 CORS 白名单同步配置（gateway-service 已具备 CORS 能力）
- iOS 双端**长期保留维护**（正式交付形态），H5 为临时演示渠道，两端双轨并行；H5 改动不得破坏 iOS 依赖的现有 API 契约
