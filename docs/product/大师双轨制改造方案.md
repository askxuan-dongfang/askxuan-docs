# 大师双轨制改造方案（寺庙绑定大师 + 野生大师）

> 版本 v0.1（2026-08-16，待确认后实施）
> 范围：后端 + iOS C端/法师端 + 三管理台 + 原型 + 文档

## 一、目标模型

### 1.1 大师两类

| 维度 | 第一类：寺庙绑定大师 | 第二类：野生大师 |
|---|---|---|
| 归属 | 寺庙强绑定（`temple_code` 非空） | 无寺庙（`temple_code=''`，平台管理） |
| 管理方 | 寺院管理台（上下架/编辑/账号） | 平台管理台（资质认证 → 审核 → 分发账号） |
| 客户端 | 法师客户端（含寺庙协同功能：加持任务、寺庙排期） | 法师客户端（仅个人功能：咨询/服务预约/收益） |
| 曝光位置 | 找寺院 → 寺院详情页大师列表 | 找师傅专栏（大师广场/法师列表） |
| 服务提供 | 寺庙服务标签（可全寺执行，或指定本寺大师执行） | 大师服务标签（自定价） |
| 收益 | 全寺执行→寺庙；大师执行→寺庙+大师分流 | 平台+大师分流（比例可配置） |
| 对接路径 | ①直接预约寺庙服务（可选指定大师）②跳过寺庙直连大师：先付费咨询→再发起服务 | 先付费咨询→再发起服务 |

### 1.2 服务标签双轨

- **寺庙标签**：现有 `service_type` 目录（S001-S013 固定）+ 寺院定价，即"寺庙所提供"。复用现有 temple_service 关联表。
- **大师标签**：新增 `master_service_tag(master_code, service_code, price, status)`，即"大师所提供"。两类大师都可配置；野生大师必备（其上架前提）。

## 二、数据模型改动

1. `askxuan_master.master` 新增列：
   - `manage_by VARCHAR(16) NOT NULL DEFAULT 'temple'`（temple/platform）
   - 现有大师全部为 temple；野生大师 `temple_code=''`。
2. 新表 `askxuan_master.master_service_tag`：
   ```sql
   CREATE TABLE master_service_tag (
     id BIGINT AUTO_INCREMENT PRIMARY KEY,
     master_code VARCHAR(16) NOT NULL,
     service_code VARCHAR(16) NOT NULL,      -- 复用 S001-S013 目录
     price DECIMAL(10,2) NOT NULL DEFAULT 0,
     status VARCHAR(16) NOT NULL DEFAULT 'enabled',  -- enabled/disabled/pending_review
     create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
     update_time DATETIME ... ON UPDATE,
     UNIQUE KEY uk_master_service (master_code, service_code)
   ) COMMENT='大师服务标签';
   ```
3. 种子数据：新增 3-5 个野生大师（manage_by=platform、temple_code=''、资质已认证）及其服务标签。
4. 咨询前置：booking 新增大师直约时校验"存在该用户→该大师的已付费咨询记录"（复用 booking_chat/consultation 表）。

## 三、API 改动（后端）

| # | 接口 | 说明 |
|---|---|---|
| 1 | `GET /api/v1/masters` | 增加 `manageBy=platform` 过滤（找师傅专栏只返回野生大师）；默认行为待定 |
| 2 | `GET /api/v1/masters/:id` | 返回新增 `manageBy`、`serviceTags`（大师标签列表） |
| 3 | `POST /api/v1/admin/masters/:id/service-tags`（法师端） | 配置/更新大师服务标签 |
| 4 | `GET /api/v1/admin/masters/:id/service-tags`（法师端） | 查询我的服务标签 |
| 5 | `POST /api/v1/masters/:id/bookings`（C端，大师直约） | 野生大师/绑定大师直约服务（校验：已付费咨询 + 标签上架） |
| 6 | 平台审核 | 野生大师资质审核复用现有法师审核流 + 服务标签审核 |
| 7 | finance 分账 | 野生大师订单结算：platform+master 比例（新配置 `wild_master_platform_rate`，默认 10%） |

## 四、各端改动

### 4.1 iOS C端
- 寺院详情：底部"预约服务"按钮已删（bug）；服务区=寺庙标签；大师列表=本寺绑定大师。
- 找师傅列表：仅野生大师（manageBy=platform）。
- 大师详情页（两类通用）：展示服务标签；"先咨询"（付费咨询入口，已有）→ 咨询后开放"预约服务"（大师直约）。
- 大师广场（社区）不变。

### 4.2 iOS 法师端
- 新增「我的服务标签」管理（选择 S001-S013 + 定价）。
- 野生大师：隐藏寺庙协同功能（加持任务、寺庙排期、寺庙收入）。
- 两类大师收益明细按新分账展示。

### 4.3 寺院管理台
- 大师列表：仅显示本寺绑定大师（隔离已修复）；可配置"大师执行"的服务标签与分流。

### 4.4 平台管理台
- 法师审核：区分两类（寺庙绑定 / 野生）；野生大师需资质认证后上架并分发账号。
- 大师服务标签审核（野生大师标签变更需平台审核）。

### 4.5 原型 + 文档
- 找师傅原型改野生大师；大师端原型加标签管理；更新统一数据字典/业务流程/状态机/API-REFERENCE。

## 五、实施阶段
