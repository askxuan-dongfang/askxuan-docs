# 管理平台业务模型与迁移约定

版本：v1 · 2026-10-21 · **待实施方案**。本文定义后台改版的业务边界与迁移要求，不代表接口、权限、数据迁移或新保存流程已经实现。审查基线为 frontend `ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2`、backend `90c474bc4100dac5da495247d37f19e5f40e6609`；下列风险来自固定源码审查，未经线上写入复现，不作为线上数据失配结论。

## 1. 术语与权威源

| 业务概念 | 权威源与既定约束 | 本轮约定 |
|---|---|---|
| 信仰类型 | `beliefCode`；汉传、藏传、南传佛教、道教、民间信仰五类 | 保留五类；首页图标、文案、排序属于展示配置，不另建分类 |
| 宗派 / 信俗 | `directory_tag` 与 `provider_directory_tag`；`traditionCodes` 为关联结果 | 保留多选和兼祀，不新增主次宗派字段；编码用于筛选，名称可更改 |
| 宗派资料文本 | `sect`；历史资料和现有编辑接口仍使用 | 不自动覆盖关联标签，不取多标签首项替代文本；最终表单名称待设计决定 |
| 地区归属 | `region_tag`、`provider_region` 与有效 `regionCode` | 标准地区用于筛选；寺院绑定师傅可继承寺院地区，也可保留显式覆盖 |
| 地理文字 | `region`、`address` | 保留所在省市、地点和地址原文；不能代替标准地区编码 |
| 身份与擅长 | `position`、`specialties` 及资料选项 | 保留资料能力；不因客户列表取消对应筛选而删除字段或选项 |
| 标准服务 | S001—S013 的 `service_type` | 保留十三项；实际可提供服务以提供者服务及其有效状态为准，不从“擅长”推定 |
| 心愿 | `intent_tag` 与默认服务规则、提供者绑定 | 保留 `peace/wealth/love/career/study/taisui/rite` 七码；继承、自定义和显式空选分别解释 |

当前存在两项数据分离：资料保存只改 `sect`，标签另走关联保存；寺院表单只改地区文字，标准地区另行设置。客户目录按标准编码筛选，因此改资料文字不等于改筛选归属。见[师傅资料保存](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/master/MasterDetailView.vue#L138-L152)、[标签关联](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/components/ProviderDirectoryTags.vue#L24-L25)、[寺院资料提交](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-temple-admin/src/views/TempleInfoView.vue#L58-L67)、[目录编码过滤](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/ios-customer/DongFangApp/Features/Temple/TempleListViewModel.swift#L35-L42)。

## 2. 维护入口与下游影响

以下为建议入口，不是已经上线的菜单：

| 建议分区 | 维护内容 | 保存前说明的影响 |
|---|---|---|
| 基础标准 | 五类、宗派信俗、地区、人员资料选项、十三标准服务、七心愿及默认关联 | 引用对象数量、前台名称、筛选选项和有效关联；停用不等于删除历史关系 |
| 机构与人员 | 寺院 / 师傅资料、标准归属、地区与继承来源 | 哪些字段仅展示、哪些改变目录命中；多信俗同时可见，不藏在编辑弹窗内 |
| 服务经营 | 提供者实际服务、价格、启停、心愿例外 | 区分标准服务、实际经营服务与咨询；显示当前规则来源和有效结果 |
| 首页与内容运营 | 首页展示与落地编排 | 引用标准编码；改首页排序不修改提供者归属 |
| 内容治理 | 敏感词 | 将现“数据字典”准确命名，避免与业务基础标准混淆 |

平台列表筛选选项须来自完整标准目录，不从当前分页记录提取；现有实现见[师傅列表](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/master/MasterListView.vue#L149-L155)。心愿来源保留“跟随标准 / 手动配置 / 恢复默认”，自定义空选表示不进入心愿页，不能自动恢复继承。见[规则解析](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/commerce/product-service/internal/model/service_intentions.go#L14-L24)。

当前“首页分类”可新增通用编码，但子信俗只接受五类、服务心愿绑定只接受七码。方案先按既定范围收敛入口，不开放第六类、第八心愿或第十四标准服务。未来扩展须另行设计完整契约。依据：[分类创建](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/settings/SettingsTaxonomyView.vue#L49-L78)、[五类校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/model/directory_tag.go#L38-L45)、[七码校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/commerce/product-service/internal/model/service_intentions.go#L63-L69)。

## 3. 三端与角色边界

| 管理端 / 角色 | 当前已核实边界 | 改版要求 |
|---|---|---|
| 平台管理端 `platform_super` | 宗派信俗目录、关联及地区标准写入受超级管理员校验 | 沿用现权；调整菜单不改变接口授权 |
| 平台其他角色 | 不能因新页面可见而推定可写 | 按现有后端校验逐项接入；无权动作只读或隐藏，直接请求仍须拒绝 |
| 寺院管理端 | 可维护本寺资料与纳管师傅；已有表单可提交 `sect`、地区文字 | 明示这些编辑不等于取得标准标签 / 地区目录写权限，不扩大机构作用域 |
| 师傅工作台（H5 / 原生） | 本人资料更新开放简介、擅长、头像、定价说明；不包含身份、信仰类型、宗派或标准地区 | 保留本人及绑定限制；擅长不是服务资质或认证身份 |

依据：[标准目录授权](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/handler/directory_tag.go#L12-L20)、[超级管理员校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/handler/region.go#L24-L34)、[寺院师傅编辑契约](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-temple-admin/src/api/master.ts#L34-L38)、[本人更新实现](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/master-service/internal/logic/workspaceprofilelogic.go#L75-L118)。

“提供者申请调整标准归属 → 平台审核”是候选未来流程，尚未实现；需先明确申请人、审批人及生效节点。三端统一的是数据含义、状态和权限结果，不要求拥有相同写权限。

## 4. 状态与保存一致性

| 状态维度 | 含义 | 禁止混用 |
|---|---|---|
| 认证 `authStatus` | 资格审核结果 | 已认证不等于已上架 |
| 经营 `shelfStatus` | 提供者上架 / 下架 | 下架不等于平台封禁或删除账号 |
| 平台 `platformStatus` | 正常 / 封禁 | 解封不自动重办认证或重启服务 |
| 字典、服务启停 | 标准项或实际服务可用性 | 停用不抹除历史订单、关联及审计 |
| 地区覆盖 / 继承 | 有效值的来源 | 清空覆盖值意味着恢复继承，不是清空所属寺院地区 |

各状态单独展示操作原因及结果；改版不合并状态机，不新增未经合同支持的跳转。见[师傅状态定义](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/master-service/internal/model/master.go#L15-L57)、[地区继承与覆盖](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/model/region.go#L67-L101)。

平台师傅当前一次“保存”先写资料，再写服务标签，第二步失败时统一报失败，存在部分成功风险；尚未在线复现。[现有双请求](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/master/MasterDetailView.vue#L138-L157)。建议原型按资料、归属、服务分段保存：独立显示未修改、保存中、成功、失败和刷新结果，保留失败草稿，只重试失败段。若采用整页原子保存，须另行设计统一业务命令，不宣称现有两次请求具有事务。并发冲突、幂等和版本策略仍待实现契约明确。

## 5. 迁移核验与回退

1. 先只读盘点标准项、资料文本、关联、地区覆盖 / 继承与服务来源，记录基线和摘要；差异不是自动判错依据。
2. 保留编码、旧文本、多信俗、身份擅长、现有权限及订单快照；不得无依据回填、合并、删除或从文字猜测地区。历史跨类关联逐条确认，不能因调整层级静默清除。
3. 明确映射与受影响对象后再设计迁移；关系写入先完整校验，再提交整组替换。保留现有[关联事务校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/model/directory_tag.go#L124-L154)能力。
4. 核验前后分类 / 关联数量及摘要、兼祀命中、地区继承、启停、心愿继承 / 空选、分页筛选、权限拒绝、部分保存与旧客户端兼容；原型示例通过不等于真实接口通过。
5. 发布前保留可恢复备份、旧版本、变更清单和回退步骤；回退配置 / 代码 / 数据分别验证。保留业务增量，不直接用整库旧备份覆盖迁移后的新订单。
