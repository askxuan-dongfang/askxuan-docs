## 1. 术语与权威源

| 业务概念 | 权威源与既定约束 | 本轮约定 |
|---|---|---|
| 信仰类型 | `beliefCode`；汉传、藏传、南传佛教、道教、民间信仰五类 | 保留五类；首页图标、文案、排序属于展示配置，不另建分类 |
| 宗派 / 信俗 | `directory_tag` 与 `provider_directory_tag`；`traditionCodes` 为关联结果 | 保留多选和兼祀，不新增主次宗派字段；编码用于筛选，名称可更改 |
| 宗派资料文本 | `sect`；历史资料和现有编辑接口仍使用 | 不自动覆盖关联标签，不取多标签首项替代文本；最终表单名称待设计决定 |
| 地区归属 | `region_tag`、`provider_region` 与有效 `regionCode` | 标准地区用于筛选；寺院绑定师傅可继承寺院地区，也可保留显式覆盖 |
| 地理文字 | `region`、`address` | 保留所在省市、地点和地址原文；不能代替标准地区编码 |
| 身份与擅长 | `position`、`specialties` 及资料选项 | 保留资料能力；不因客户列表取消对应筛选而删除字段或选项 |
| 标准服务 | S001—S013 的 `service_type` | 保留十三项；实际可提供服务以提供者服务及其有效状态为准，不从“擅长”推定 |
| 心愿 | `intent_tag` 与默认服务规则、提供者绑定 | 保留 `peace/wealth/love/career/study/taisui/rite` 七码；继承、自定义和显式空选分别解释 |

当前存在两项数据分离：资料保存只改 `sect`，标签另走关联保存；寺院表单只改地区文字，标准地区另行设置。客户目录按标准编码筛选，因此改资料文字不等于改筛选归属。见[师傅资料保存](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/master/MasterDetailView.vue#L138-L152)、[标签关联](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/components/ProviderDirectoryTags.vue#L24-L25)、[寺院资料提交](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-temple-admin/src/views/TempleInfoView.vue#L58-L67)、[目录编码过滤](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/ios-customer/DongFangApp/Features/Temple/TempleListViewModel.swift#L35-L42)。

## 3. 三端与角色边界

| 管理端 / 角色 | 当前已核实边界 | 改版要求 |
|---|---|---|
| 平台管理端 `platform_super` | 宗派信俗目录、关联及地区标准写入受超级管理员校验 | 沿用现权；调整菜单不改变接口授权 |
| 平台其他角色 | 不能因新页面可见而推定可写 | 按现有后端校验逐项接入；无权动作只读或隐藏，直接请求仍须拒绝 |
| 寺院管理端 | 可维护本寺资料与纳管师傅；已有表单可提交 `sect`、地区文字 | 明示这些编辑不等于取得标准标签 / 地区目录写权限，不扩大机构作用域 |
| 师傅工作台（H5 / 原生） | 本人资料更新开放简介、擅长、头像、定价说明；不包含身份、信仰类型、宗派或标准地区 | 保留本人及绑定限制；擅长不是服务资质或认证身份 |

## 4. 状态与保存一致性

| 状态维度 | 含义 | 禁止混用 |
|---|---|---|
| 认证 `authStatus` | 资格审核结果 | 已认证不等于已上架 |
| 经营 `shelfStatus` | 提供者上架 / 下架 | 下架不等于平台封禁或删除账号 |
| 平台 `platformStatus` | 正常 / 封禁 | 解封不自动重办认证或重启服务 |
| 字典、服务启停 | 标准项或实际服务可用性 | 停用不抹除历史订单、关联及审计 |
| 地区覆盖 / 继承 | 有效值的来源 | 清空覆盖值意味着恢复继承，不是清空所属寺院地区 |

各状态单独展示操作原因及结果；改版不合并状态机，不新增未经合同支持的跳转。见[师傅状态定义](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/master-service/internal/model/master.go#L15-L57)、[地区继承与覆盖](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/model/region.go#L67-L101)。

设计审查时，平台师傅一次“保存”先写资料，再写服务标签，第二步失败时统一报失败，存在部分成功风险；该风险未在线写入复现。[现有双请求](https://github.com/askxuan-dongfang/askxuan-frontend/blob/ee7e48ee1f70b1d5b6adcb0c4147b5478b7793f2/apps/web-platform-admin/src/views/master/MasterDetailView.vue#L138-L157)。原型按资料、归属、服务分段保存：独立显示未修改、保存中、成功、失败和刷新结果，保留失败草稿，只重试失败段。若采用整页原子保存，须另行设计统一业务命令，不宣称现有两次请求具有事务。本轮 P0 接入资料和服务各段结果及独立重试；并发冲突、统一保存命令和版本策略仍属于后续合同。

## 5. 迁移核验与回退

1. 先只读盘点标准项、资料文本、关联、地区覆盖 / 继承与服务来源，记录基线和摘要；差异不是自动判错依据。
2. 保留编码、旧文本、多信俗、身份擅长、现有权限及订单快照；不得无依据回填、合并、删除或从文字猜测地区。历史跨类关联逐条确认，不能因调整层级静默清除。
3. 明确映射与受影响对象后再设计迁移；关系写入先完整校验，再提交整组替换。保留现有[关联事务校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/90c474bc4100dac5da495247d37f19e5f40e6609/services/content/temple-service/internal/model/directory_tag.go#L124-L154)能力。
4. 核验前后分类 / 关联数量及摘要、兼祀命中、地区继承、启停、心愿继承 / 空选、分页筛选、权限拒绝、部分保存与旧客户端兼容；原型示例通过不等于真实接口通过。
5. 发布前保留可恢复备份、旧版本、变更清单和回退步骤；回退配置 / 代码 / 数据分别验证。保留业务增量，不直接用整库旧备份覆盖迁移后的新订单。

## 6. 本轮决定与后续待决项

本轮已确定 `sect` 展示为“宗派补充说明”、普通文字编辑保留历史关系、冲突主类型改动拒绝，以及资料 / 服务各段独立结果和重试。不会新增提供者归属变更申请，也不因初始归属采集扩大已有写权限。

P1/P2 继续待定：跨段回读和版本冲突协议、统一业务命令、引用影响和前台预览、待办 / 订单聚合，以及未来是否引入归属变更申请。不得将本轮最小保存反馈或已有申请修订号视为整页并发协议已经实现。

## 7. P0 接口、兼容与部署合同

### 7.1 五类与标准多选

五类编码固定为 `han_buddhism`、`tibetan_buddhism`、`theravada_buddhism`、`daoism`、`folk`；旧 `taoism` 接收后归一为 `daoism`。沿用当前 24 项宗派 / 信俗基线，不新增类别。`sect` 保留原文，不用于猜测 `beliefCode` 或 `traditionCodes`。

| 合同 | 本轮要求 |
| --- | --- |
| 申请资料 | `WorkProfile` 增量字段 `traditionCodes: string[]`，最多 12 项；草稿允许空选，不自动清空未解决的选择 |
| 提交 / 批准 / 新建 | 必须 1—12 项；编码合法且不重复，每项为当前主信仰下已启用的 `tradition`；数据库中再次核验，不能只信任表单 |
| 四入口 | 寺院入驻批准、独立大师认证批准、寺院新建大师、平台新建大师；校验失败不得留下半成品资料、有效关联或账户数据库副作用 |
| 审核时目录变化 | 提交后到批准前停用、更换父类等变化须重新校验；批准失败不改变 `submitted` 及其修订版本 |
| 旧 `submitted` 缺编码 | 明确拒绝批准并保留 `submitted`；审核人员按既有退回流程填写原因，申请人在 `rejected` 状态补填再提交；不后台补猜或直接改成 `draft` |
| 旧申请省略 / `null` | 保存时保留已有 `traditionCodes`；若此前没有，草稿仍可保存，正式提交仍受非空及目录校验 |
| 正式资料省略 / `null` | 不替换已有关系；普通文字编辑保留历史停用、未知、跨父项，界面解释为历史关联；冲突的主信仰改动拒绝 |
| 关系新增 / 改动 | 新增项必须有效同父；历史保留不是允许新建跨父关系。已有关系修改仍限 `platform_super`，寺院 / 本人不能借资料更新提交关系改动 |

公开 `GET /api/v1/beliefs/directory-tags` 返回 `data.list`，字段为 `code`、`group`、`beliefCode`、`name`、`value`、`sort`、`status`，仅返回 `enabled` 项；表单取其中 `group=tradition`。管理端全量目录与既有授权不变，用于标准维护、停用及历史解释。公开可选项数量随启停变化，不硬编码为 24。

平台寺院 / 大师列表增量支持 `traditionCode`，在 SQL 中先筛选，再以同一条件计数及分页。筛选选项来自完整目录，零结果或换页不改变选项；旧 `sect` 文字过滤保留兼容含义，不伪装成标准编码过滤。

### 7.2 一致性与权限

审核批准和新建大师在同一数据库事务内完成资料、标准关联及既有角色 / 账户等数据库副作用；任一步失败需回滚，重试不得重复创建。关联整组写入前完成校验，并以 `FOR SHARE` 保护目录及跨服务只读核验，避免为加锁而扩大写权限。认证审核将可变申请人 `admin_account` 排他锁与只读 `role` 共享锁分开；已有申请的修订号及状态限制继续生效。本人更新头像 / 擅长采用只写 `avatar/specialties` 的专用 SQL，避免把读取时的陈旧信仰、宗派说明或标准关系覆盖回去。
