# 问玄东方：当前产品与方案总纲

文档基线：2026-11-09；产品版本：0.0.1。面向产品、设计、运营及交付负责人。产品操作以[产品使用手册](../guides/产品使用手册.md)为准，发布和真实业务验证范围见[能力边界](产品现状与能力边界.md)。

## 1. 产品定位与服务对象

问玄东方连接文化内容、寺院与师傅服务、东方珠作 DIY 和 AI 专题解读，让用户从了解、选择到预约、创作、查看记录，在同一产品中完成任务。东方珠作是 DIY 创作子品牌；AI 解读提供文化与自我探索参考，不以预测结果或生成速度承诺服务效果。

| 对象 | 核心任务 | 主要资料 |
| --- | --- | --- |
| 投资与合作决策人 | 理解价值、业务闭环、商业假设、验证进展与下一阶段投入 | 发布介绍、投资侧说明、运营合作册 |
| 初次接触的普通用户 | 看懂产品、选择入口、完成首次体验 | 产品交付与上手指南 |
| 信众与日常服务用户 | 找寺庙/师傅、预约、查进度与回执、DIY、阅读报告、查看资产 | 产品使用手册及任务分册 |
| 寺院管理员 | 入驻、维护本寺资料/人员/服务、排班、履约、跟进异常与核账 | 寺院入驻与运营手册 |
| 独立或纳管大师 | 入驻/激活、维护本人服务与日程、执行、沟通、提交回执与查收益 | 大师入驻与服务手册 |
| 平台与合作运营 | 供给审核、内容与商品运营、活动、财务核对、试点交付 | 运营与合作手册 |
| 设计、研发、测试 | 保持体验和规则一致、明确版本与验收边界 | 视觉与交互册、能力边界、需求/测试资料 |

“用户”是总称，“信众”是产品中的客户身份；“大师/法师/师傅”分别用于合作对象、专业端和用户界面，不新增三种账号。寺院属于组织，寺院管理员与大师本人账号分别承担管理和执行职责。

## 2. 当前信息架构

客户 H5 与信众 iOS 是两种实现，专业端有大师 H5 与 iOS；统一运营管理台包含商城，寺院台独立。旧商城入口仅做迁移。macOS 入口不等于全部业务另有原生实现。

首页找寺庙在左、找师傅在右，文字居中；不显示信仰类别分区。现有七个心愿保留，左侧“按心愿办”为固定纯文字标题，仅右侧入口横向滑动。DIY 区仅保留“开始设计”主入口，进入 `/c/diy?tab=plaza`；二级页面切换“设计广场 / 我的设计”，并从该页进入编辑器。主入口下方以 8px 间距直接展示少量公开作品的横滑预览，不另设“广场精选”标题；无公开作品时整条推荐隐藏，不留空入口或示例。

Web 普通卡片和按钮通过主题底色、间距与色差分组，默认无描边；焦点、选中、输入错误和必要数据分隔继续明确。页面只保留一个主标题，删除同义眉题和重复副说明；费用、权限、审核、模拟状态等会影响决定的信息在相应操作处保留。本次实施限 Web，iOS 暂不同步。

当前首页积分入口保留现有文案与目标映射：商城→积分转盘，转盘→积分商城，乐购→奖池。以落地页功能标题识别玩法，不能凭首页名称推断现金商城。现金购物使用独立商城入口。

目录以信仰、宗派、类型及地区等标准归属组织；找师傅突出提供服务和价格范围。身份资料、目录归属和可售服务是不同字段，运营不可自行用标签代替审核关系。

## 3. 模块与规则统一表

| 模块 | 当前规则 | 对外表达与操作重点 |
| --- | --- | --- |
| 账号与入驻 | 邮箱注册/激活/找回；独立大师申请、寺院入驻、纳管大师激活；平台账号受控开通 | 先选身份；资料、资格及账号权限分别审核 |
| 预约与服务 | 从选择服务到执行、回执确认，按原订单状态推进 | 支付、执行和确认完成分别判断；异常回原单处理 |
| DIY | 真 3D 悬挂预览、八个材料筛选入口（含正在使用/全部）和独立连接/配件；本机草稿、账号保存、订单快照与公开定稿分开 | 保存不是发布；公开定稿只读，继续创作保留草稿/副本 |
| 广场发布与创作者 | 本人同款、成功支付、审核确认及有效快照是发布条件；新源码允许合格模拟订单展示 | 付款渠道记录不改写，模拟来源不产生真实返利归因；新后端线上资格仍需专项验收 |
| AI 问事 | 十二专题、资料/地区与时间输入、生成、免费摘要、钱包解锁、历史回看与追问 | 当前价格按专题和收银报价；报告生成成功与内容质量通过分开 |
| 钱包 | 正式与演示余额隔离，统一报价/收银，创作收益与用户余额分账 | 演示扣账不是实际收款，提现申请不是银行到账 |
| 积分 | 兑换、积分转盘、奖池及独立流水；AI 积分解锁已退役 | 转盘允许多次参与，奖池每人每期一次，以活动实际规则为准 |
| 成长 | 五级成长值与权益，任务/交易资格、额度、退款回冲和服务端报价 | 统一使用成长值；不可支付/提现，不增加中奖概率 |
| 平台与寺院管理 | 平台十工作区；寺院七组导航、每寺现有管理员统管本寺业务 | 平台岗位权限与寺院管理员不是同一套子账号模式；不能跨组织操作 |

## 5. 发布会与对外交付原则

先讲对象和问题，再讲用户旅程、合作分工和已验证案例；功能演示从已审核可公开的资料开始。对外只分发对应受众资料，测试夹具、账号、原始运行日志和私有恢复材料不随包交付。

对外可表述“具备相关产品模块和可追溯流程”，具体上线或验证结论须带范围。不能表述“十二类报告全部通过”“正式支付与银行结算全部打通”“全部 iOS 真机验证完成”，也不能用模拟订单和余额推导营收、用户留存或投资回报。

文档规则更新不等于部署、公开作品、模型调用、资金操作或设备分发已经完成。各端的已知历史结果和剩余关卡见[能力边界](产品现状与能力边界.md)；未来每次产品变化同时更新总纲、对应受众手册、专业规则及分发版，不再依赖读者拼接增量报告。
