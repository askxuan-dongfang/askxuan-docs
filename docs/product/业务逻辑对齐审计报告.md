## 一、预约服务闭环

### 现状分析

| 环节 | 状态 | 说明 |
|------|------|------|
| C端入口 → booking.html | **完整** | 7个服务页面(service-blessing/lamp/incense/vow/rite/consecration/taisui)均有"立即预约"入口，temple-detail和master-profile也有预约入口，均指向booking.html |
| booking-list(寺院管理台) | **基本完整** | 能看到预约记录，包含订单号/用户/服务项目/预约日期/时段/金额/状态。服务项目格式为"服务名 / 法师名 / 寺院名" |

### 发现的问题

**[Gap-1] C端有8个热门服务入口，但寺院管理台service-list仅管理7项**
- **详情**: C端首页"热门服务"区域有: DIY手串、祈福、供灯、上香、还愿、超度、开光、化太岁 共8个入口(其中DIY手串不是寺院服务)。寺院管理台service-list页显示"共7项服务"(祈福法会/供灯祈福/上香礼佛/超度法事/化太岁/开光加持/还愿)，这7项与C端的7个寺院服务恰好对齐。但DIY手串不在此管理范围内，归属商城管理台。
- **结论**: **对齐正常，无Gap。**

**[Gap-2] 法师工作台booking-detail中"命理咨询"服务类型在寺院管理台service-list中不存在**
- **详情**: 法师工作台bookings.html中有"命理咨询"预约(赵六/线上视频)，但寺院管理台service-list的7项服务中无"命理咨询"。该服务类型在所有管理端都未被管理。
- **缺失**: 寺院管理台service-list缺少"命理咨询"服务类型，或者法师工作台的示例数据有误
- **状态**: **待处理** — 将在 Phase 1 补全
- **建议**: 在寺院管理台service-list中增加"命理咨询"服务类型，或确认该服务是否由法师自行管理(若如此，则法师工作台skills.html应能管理)

## 二、DIY手串加持服务闭环 (CRITICAL)

### 现状分析

C端diy-order.html页面提供4种额外加持服务:
- 灵隐寺开光(智海法师 / ¥168)
- 白云观祈福(清风道长 / ¥128)
- 少林寺加持(释延心法师 / ¥198)
- 大昭寺灌顶(扎西多吉活佛 / ¥268)

商城管理台diy-order-detail.html中展示了"额外服务"卡片，包含服务名称/执行寺庙/主法法师/服务费用/服务时长信息。

### 发现的问题

**[Gap-3] 加持任务无法到达寺院管理台 -- 已修复 ✅**
- **详情**: 商城管理台diy-order-detail.html显示了"灵隐寺开光"的额外服务信息，但订单状态流程为: 提交订单 → 审核确认 → 开始制作 → 制作完成 → 发货 → 完成。**整个流程中没有任何"发送加持任务到寺院/法师"的环节**。
- **缺失内容**:
  1. 寺院管理台sidebar导航没有"加持任务"或"DIY加持"模块
  2. 寺院管理台dashboard.html的待办事项中没有加持相关任务
  3. 寺院管理台没有任何页面接收来自商城的加持工单
- **需要新增的模块**:
  - 寺院管理台: 新增"加持任务"(blessing-tasks)页面，sidebar导航"运营"区域增加入口
  - 逻辑连接: 商城管理台"制作完成"后，若订单含加持服务 → 自动创建加持工单 → 推送到对应寺院管理台
- **状态**: **已修复 ✅** — temple-service 已有 blessing-tasks admin 端点

**[Gap-4] 加持任务无法到达法师工作台 -- 已修复 ✅**
- **详情**: 法师工作台workspace.html的"今日预约"仅显示线下预约(祈福法会/命理咨询/开光加持)，**没有"DIY手串加持任务"入口**。
  - 法师工作台bottom-tabs仅有: 工作台/预约/消息/我的，无"任务"tab
  - 工作台quick-actions仅有: 设置日程/休息请假/个人主页/收入提现，无"加持任务"
- **缺失内容**:
  1. 法师工作台需要一个"加持任务"列表，区别于"预约"(预约是线下面对面服务，加持是对物品的远程/线下仪式)
  2. 法师需要能"接受任务 → 完成加持 → 上传凭证/视频 → 确认完成"的完整流程
- **需要新增的模块**:
  - 法师工作台: 新增blessing-task-list页面和blessing-task-detail页面
  - workspace.html增加"待加持"统计卡片和"加持任务"快捷入口
  - bottom-tabs增加"任务"tab，或在"工作台"首页增加加持任务section
- **状态**: **已修复 ✅** — master-service 已有 workspace blessing-tasks 端点

**[Gap-5] 商城管理台diy-order-detail缺少加持状态追踪 -- 已修复 ✅**
- **详情**: diy-order-detail.html的status-steps为: 提交订单→审核确认→开始制作→制作完成→发货→完成。没有"等待加持/加持中/加持完成"的中间状态。
- **缺失**: 订单额外服务卡片展示了加持信息，但status timeline中没有对应步骤，操作按钮仅有"审核通过/开始制作/确认发货/取消"，没有"发送加持"或查看加持进度的按钮。
- **需要修改**:
  - status-steps增加"加持中"步骤(在"制作完成"和"发货"之间)
  - 增加持状态显示: 等待加持 / 加持中 / 加持完成
  - 增加"发送加持"按钮(制作完成后触发)
  - 增加持进度追踪(显示法师是否已接受、加持是否已完成)
- **状态**: **已修复 ✅** — DiyOrder 返回 BlessingTask 字段

## 核心断裂链路图

```
C端用户下单DIY手串(选加持)
       │
       ▼
商城管理台 dii-order-list ──── 审核通过 → 制作中 → 制作完成
                                              │
                                    【此处断裂 - Gap-3/4/5/6】
                                              │
                              ┌────────────────┼────────────────┐
                              ▼                ▼                ▼
                      应发送到           应发送到          应通知到
                      寺院管理台         法师工作台           C端用户
                      加持任务页面        加持任务页面        加持进度
                      [不存在]           [不存在]            [不存在]
```

**结论**: DIY手串加持服务是整个平台最核心的跨端业务闭环，目前前端实现存在严重断裂。商城管理台虽然有加持服务的配置和展示，但缺少向寺院管理台和法师工作台派发加持任务的界面和状态流转机制。需要优先补齐这3端的加持任务功能。
