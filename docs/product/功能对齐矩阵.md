- 产品原型：`node scripts/audit-prototype.mjs`，112 页、1726 个站内相对引用、缺失目标 0。
- HTTP 契约：`node scripts/audit-api-reference.mjs`，运行时 292、文档 292、缺失 0、过期 0。
- 后端：21 个 Go workspace module（含 common）全部测试通过；25 个 askXuan Compose 容器健康；6 个 zrpc key 注册正常。
- 客户端：两个 iOS arm64 无签名和真机签名构建通过并安装到两台真机；三个 Web、Mock 构建及备用 Expo TypeScript 检查通过。
- 业务脚本：`test-consultation-chat-closed-loop.sh` 在 ECS 完成 13/13，覆盖报价、支付幂等、预约隔离、平台总账分账、双端会话和 OpenIM 双向收发/回调；原付费预约聊天脚本继续保留兼容回归。
- 数据约束：`bash scripts/audit-data-invariants.sh`，预约计价/占位、支付金额、商城明细、DIY 计价、加持关联与凭证、价格库存、评论状态共 13/13 通过。

## 5. 不能宣称生产完成的能力

1. 真实短信验证码、密码哈希迁移及生产认证风控。
2. 微信/支付宝支付、真实快递、银行/代付 Provider。
3. 寺院和商城经营报表的权威事件读模型。
4. 云 AI、VOD、直播/TRTC 的生产账号、回调域名和容量验收。
5. 关键 MQ 的事务型 outbox 与补偿扫描。
6. 自动/增量备份、保留策略、恢复演练和自动维护模式。
7. C 端收藏、账户安全、功德值/积分资产及大师商品/视频二级页。
8. 生产网络隔离：只暴露 gateway、OpenIM 和必要对象存储入口，禁止直连下游管理端口。

因此，当前准确结论是：**本地开发主闭环和五端构建正常，代码、原型与文档已按实际能力对齐；生产功能并未全部完成，以上 8 项关闭前不能承诺正式上线能力。**
