## 1. 端、角色与部署包

“信众、法师、寺院、商城、平台”是五类业务角色，不等于五套仍各自独立运营的前端。H5 有信众和法师两棵路由；原生 iOS 有两个工程；管理 Web 保留三个构建包，其中商城包只承担旧链接兼容。

| 用户/角色 | 当前入口与实现 | 能力边界 |
|---|---|---|
| 信众 | H5 `/c/*`；`apps/ios-customer/DongFangApp` | 发现/预约/咨询/商城/DIY/积分活动/个人中心；两种实现保持业务语义，不承诺逐像素一致 |
| 法师 | H5 `/m/*`；`apps/ios-master/MasterApp` | 工作台、预约履约、排班、聊天、加持、内容、收益与设置 |
| 平台运营 | `apps/web-platform-admin`，部署 `/admin/` | 平台业务及统一商城运营模块；平台权限和商城权限仍按角色守卫区分 |
| 寺院运营 | `apps/web-temple-admin`，部署 `/temple/` | 寺院资料、服务、法师、预约、加持分配、评价与报表 |
| 商城运营 | 正式业务 `/admin/commerce/*`；`apps/web-shop-admin` 部署 `/shop/` | `/shop/*` 只兼容跳转，保留详情路径、查询和 hash；已有平台会话优先，不以商城身份获取平台权限 |

源码依据：[商城兼容入口](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/apps/web-shop-admin/src/main.ts)、[旧路由映射](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/apps/web-shop-admin/src/router/index.ts)、[统一管理路由](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/apps/web-platform-admin/src/router/index.ts)、[H5 路由](https://github.com/askxuan-dongfang/askxuan-h5/blob/v0.0.1/src/App.tsx)。旧商城目录中的业务组件和原型不能据此认定仍存在独立商城运行界面。

## 4. 登录过期与错误边界

- H5：保护请求的 HTTP 401 或业务 `40101/40102/40103` 清理当前登录并按角色回 `/c/login` 或 `/m/login`；并发失败只触发一次会话切换，旧请求不能登出新登录。JSON 封装的 200 认证失败及流式请求也有检查。
- 两个 iOS：APIClient/AuthStore 共用各自的会话策略；可恢复的 access token 先合并刷新，确认凭证失效后清理并返回登录；临时网络问题与被取消请求不冒充认证失效。
- 管理界面：共享 session-expiry 做单次刷新/失效跳转及会话代际保护，回当前管理登录入口。
- 403、角色无权限、登录时输错凭证，均不得误伤已存在的有效会话。“不再反复显示 token 无效”不是把所有错误都跳登录。

源码：[H5 session](https://github.com/askxuan-dongfang/askxuan-h5/blob/v0.0.1/src/api/session.ts)、[管理 session-expiry](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/packages/admin-ui/session-expiry.ts)、[信众 APIClient](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/apps/ios-customer/DongFangApp/Core/Network/APIClient.swift)、[法师 APIClient](https://github.com/askxuan-dongfang/askxuan-frontend/blob/v0.0.1/apps/ios-master/MasterApp/Core/Network/APIClient.swift)。

## 5. 积分活动、现金与成长值

当前抽奖是**消耗积分的活动**：转盘/奖池的 `pointsCost >= 1`，参与请求携带 `expectedPoints`，服务端检查规则一致与余额，在事务中扣 `points_account` 并写 `points_ledger`。平台独立承担奖品预算，不等于用户免费参与。

| 体系 | 当前含义 |
|---|---|
| 现金商城、预约、DIY 订单 | 各自订单/金额/支付状态；当前文档不能以 mock 成功声称真实资金支付验收 |
| 积分兑换 | 配置积分换确定权益，有独立兑换与履约记录 |
| 积分转盘/奖池 | 消耗服务端积分参与，结果和活动履约走 reward 数据模型；不把旧本地演示余额当真实资产 |
| 功德值 | 独立成长语义；不能把付款、抽奖、中奖或积分扣除自动宣称为功德增长 |

权威源码：[活动校验及积分事务](https://github.com/askxuan-dongfang/askxuan-backend/blob/v0.0.1/services/operation/marketing-service/internal/rewards/store.go#L153)、[参与请求校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/v0.0.1/services/operation/marketing-service/internal/handler/rewards.go#L105)。积分活动、成长值与现金交易分别配置、记账和验收。
