## 1. 端、角色与部署包

“信众、法师、寺院、商城、平台”是五类业务角色，不等于五套独立前端。H5 有信众和法师两棵路由；原生 iOS 有两个工程；商城完整并入总管理台后，业务管理 Web 只保留统一管理台、寺院管理台两个构建工程。

| 用户/角色 | 当前入口与实现 | 能力边界 |
|---|---|---|
| 信众 | H5 `/c/*`；`apps/ios-customer/DongFangApp` | 发现/预约/咨询/商城/DIY/积分活动/个人中心；两种实现保持业务语义，不承诺逐像素一致 |
| 法师 | H5 `/m/*`；`apps/ios-master/MasterApp` | 工作台、预约履约、排班、聊天、加持、内容、收益与设置 |
| 平台运营 | `apps/web-platform-admin`，部署 `/admin/` | 平台业务及统一商城运营模块；平台权限和商城权限仍按角色守卫区分 |
| 寺院运营 | `apps/web-temple-admin`，部署 `/temple/` | 寺院资料、服务、法师、预约、加持分配、评价与报表 |
| 商城运营 | 正式业务 `/admin/commerce/*`；统一后台产物 `dist/legacy/shop/index.html` 接管 `/shop/` | `/shop/*` 只兼容迁移，保留详情路径、查询和 hash；已有平台会话优先，不以商城身份获取平台权限；无独立商城工程或依赖 |

源码依据：[统一管理路由](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/apps/web-platform-admin/src/router/index.ts)、[H5 路由](https://github.com/askxuan-dongfang/askxuan-h5/blob/8464790809f69bc898381c31069bab2e7cac32b6/src/App.tsx)。本轮删除 `apps/web-shop-admin`，全部商城页面、路由和依赖在 `apps/web-platform-admin` 维护，寺院工程保留。迁移页由[legacy-shop.mjs](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/apps/web-platform-admin/src/compat/legacy-shop.mjs)提供，[Vite 配置](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/apps/web-platform-admin/vite.config.ts)负责生成；构建和发布边界见[技术架构](../architecture/技术架构.md)。

## 4. 登录过期与错误边界

- H5：保护请求的 HTTP 401 或业务 `40101/40102/40103` 按会话策略尝试一次共享续期；无法续期时清理当前登录并按角色回 `/c/login` 或 `/m/login`。并发失败只触发一次会话切换，旧请求不能登出新登录。JSON 封装的 200 认证失败及流式请求也有检查。
- 两个 iOS：APIClient/AuthStore 共用各自的会话策略；可恢复的 access token 先合并刷新，确认凭证失效后清理并返回登录；临时网络问题与被取消请求不冒充认证失效。
- 管理界面：共享 session-expiry 做单次刷新/失效跳转及会话代际保护，回当前管理登录入口。
- 后端续期绑定原登录身份域与客户端，拒绝缺失身份信息的旧 Refresh Token；旧会话需要重新登录，不能通过相同数字账号 ID 续成另一类身份。
- 平台消息模板、推送、日志及公告由网关与 message-service 双层要求管理身份和 `platform_super`；法师本人消息使用独立 `master` 规则及 `MasterID` 归属。商城人员、人类 `platform_service` 角色不因此获得平台消息权限；本轮不改内部 MQ 通知链路。
- 403、角色无权限、登录时输错凭证，均不得误伤已存在的有效会话。“不再反复显示 token 无效”不是把所有错误都跳登录。

源码：[H5 session](https://github.com/askxuan-dongfang/askxuan-h5/blob/8464790809f69bc898381c31069bab2e7cac32b6/src/api/session.ts)、[管理 session-expiry](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/packages/admin-ui/session-expiry.ts)、[信众 APIClient](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/apps/ios-customer/DongFangApp/Core/Network/APIClient.swift)、[法师 APIClient](https://github.com/askxuan-dongfang/askxuan-frontend/blob/f4d72ec774f095cad276aed3e4b76e23a0c8770f/apps/ios-master/MasterApp/Core/Network/APIClient.swift)。

## 5. 积分活动、现金与成长值

当前抽奖是**消耗积分的活动**：转盘/奖池的 `pointsCost >= 1`，参与请求携带 `expectedPoints`，服务端检查规则一致与余额，在事务中扣 `points_account` 并写 `points_ledger`。平台独立承担奖品预算，不等于用户免费参与。

| 体系 | 当前含义 |
|---|---|
| 现金商城、预约、DIY 订单 | 各自订单/金额/支付状态；当前文档不能以 mock 成功声称真实资金支付验收 |
| 积分兑换 | 配置积分换确定权益，有独立兑换与履约记录 |
| 积分转盘/奖池 | 消耗服务端积分参与，结果和活动履约走 reward 数据模型；不把旧本地演示余额当真实资产 |
| 功德值 | 独立成长语义；不能把付款、抽奖、中奖或积分扣除自动宣称为功德增长 |

权威源码：[活动校验及积分事务](https://github.com/askxuan-dongfang/askxuan-backend/blob/758eb6aab094e463172673f183cc23846c1bff30/services/operation/marketing-service/internal/rewards/store.go#L153)、[参与请求校验](https://github.com/askxuan-dongfang/askxuan-backend/blob/758eb6aab094e463172673f183cc23846c1bff30/services/operation/marketing-service/internal/handler/rewards.go#L105)。积分活动、成长值与现金交易分别配置、记账和验收。
