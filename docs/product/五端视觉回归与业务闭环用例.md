## 1. 验收分层

| 层级 | 数据与环境 | 证明什么 | 不能证明什么 |
|---|---|---|---|
| L1 构建 | 本地源码 | TypeScript/Vue 类型检查和生产打包可通过 | 真实接口、权限与数据正确 |
| L2 UI Mock | 本地 Vite + Playwright + 固定契约数据 | 路由可渲染、响应式、空态/失败态、关键非空卡片、控制台无异常 | ECS 网络、真实 JWT、后端状态流转 |
| ECS 公开无凭证 | ECS 已发布前端 + 公开只读接口 | 五端入口、公开 H5 路由、静态资源、4xx/5xx、破图、响应式和控制台状态 | JWT、角色权限、登录后数据与写操作闭环 |
| L3 ECS 只读联调 | ECS 已发布前端 + 真实登录 + 只读接口 | 路由、代理、认证、真实响应结构、静态资源与 OpenIM 运行时可达 | 创建、审批、支付等写操作闭环 |
| L4 ECS 受控闭环 | 专用验收账号 + 可清理的测试数据 | 五条跨端业务链路、RBAC、状态机、审计与回滚 | 长周期容量和生产峰值性能 |

任何一层通过都不得替代更高层结论。当前自动化默认运行 L1/L2；L3/L4 必须得到账号外发和业务写入授权后执行。

## 3. 自动化执行

### 3.1 命令

```bash
npm --prefix askXuan-frontend/apps/web-h5 run build
npm --prefix askXuan-frontend/apps/web-temple-admin run build
npm --prefix askXuan-frontend/apps/web-shop-admin run build
npm --prefix askXuan-frontend/apps/web-platform-admin run build
node askXuan-frontend/scripts/audit-web-api-contracts.mjs
node askXuan-backend/scripts/audit-api-reference.mjs
(cd askXuan-frontend/e2e && npx playwright test)
E2E_PUBLIC_BASE_URL=https://目标主机 npm --prefix askXuan-frontend/e2e run test:web:public
```

`test:web:public` 不读取或提交账号凭证，不执行写请求；它检查五端登录页和信众端公开路由，并把截图写入 `e2e/artifacts/web-public/<project>/`。

真实登录只允许在明确授权后启用：

```bash
(cd askXuan-frontend/e2e && \
  E2E_RUN_LIVE_AUTH=1 \
  E2E_LIVE_BASE_URL=https://目标主机 \
  E2E_CUSTOMER_PHONE=... E2E_CUSTOMER_CODE=... \
  E2E_MASTER_ACCOUNT=... E2E_MASTER_PASSWORD=... \
  E2E_TEMPLE_ACCOUNT=... E2E_TEMPLE_PASSWORD=... \
  E2E_SHOP_ACCOUNT=... E2E_SHOP_PASSWORD=... \
  E2E_PLATFORM_ACCOUNT=... E2E_PLATFORM_PASSWORD=... \
  npx playwright test)
```

真实登录模式会把测试账号凭证发送给目标服务，因此不得在未确认目标主机、数据范围和授权前执行，也不得把密码写入验收报告或截图。测试代码不保存默认密码；缺少任一所需环境变量时，在发送登录请求前失败。设置 `E2E_LIVE_BASE_URL` 后直接检查已发布页面并关闭本地 Vite 测试服务器；自签名验收证书只在该模式下由 Playwright 忽略。

### 3.2 自动断言

每个登记路由必须满足：

1. 页面主体可见，未出现 `Cannot read`、`Unhandled` 或白屏文案。
2. `documentElement.scrollWidth` 和 `body.scrollWidth` 不超过视口宽度 1px。
3. 页面完成后不存在可见的 Element Plus loading mask。
4. 未出现未豁免的 `console.error` 或 `pageerror`。
5. ≤991px 的管理台侧栏默认位于视口外，可从“切换主导航”打开并关闭。
6. 390px 主验收视口使用非空契约数据确认关键业务字段真实渲染。
7. 390px 三管理台使用非空任务数据确认移动卡片可查看且保留主操作。
8. ECS 公开矩阵把全部 HTTP 4xx/5xx、登录页破图、生产页默认密码提示和平台登录标题低对比作为失败处理。
9. H5 可见按钮、链接和角色按钮统一检查 44×44px；标记为法师关键履约动作的目标检查 48×48px。
10. 320px 专项检查订单号、支付号、任务号、金额、状态和时间不丢失关键语义。
11. H5 区分真空数据、筛选无结果、接口失败和能力关闭；OpenIM 在有效凭证前不得请求 Go/WASM 或 SDK。
12. 390px 管理台验证移动图表摘要、局部失败模块名与“—”占位；发货、提现、审核确认取消后写请求必须为 0。

仅允许豁免浏览器图标请求、`ResizeObserver` 循环通知等明确无业务影响的浏览器噪声；业务异常不得加入豁免。

## 5. 数据状态用例

| 编号 | 场景 | 前置数据 | 操作 | 期望 |
|---|---|---|---|---|
| DS-01 | 首次加载 | 请求延迟 1–3 秒 | 打开任一 P0 页面 | 保留结构或显示加载态；可返回；结束后无永久遮罩 |
| DS-02 | 真空数据 | 成功响应且 `list=[]` | 打开列表/工作台 | 说明“当前没有什么”和下一步；不显示失败 |
| DS-03 | 筛选无结果 | 总数据非空，筛选结果空 | 应用筛选 | 显示当前筛选无结果并可清除筛选 |
| DS-04 | 完整详情 | 返回符合接口文档的非空对象 | 打开详情 | 核心名称、状态、金额/时间和主操作正确 |
| DS-05 | 缺字段成功响应 | HTTP 200，但缺少详情必填嵌套对象 | 打开详情 | 明确失败/重试，不白屏、不显示 `NaN`、不永久加载 |
| DS-06 | 单接口失败 | 工作台五个聚合请求之一失败 | 刷新工作台 | 其他模块保留；失败模块不显示 0；可重试 |
| DS-07 | 全部失败 | 所有页面请求失败 | 打开页面 | 页面级错误态、返回/重试；无样例经营数据 |
| DS-08 | 无权限 | JWT 角色不匹配 | 访问受限端 | 清理当前端会话并回登录页，提示所需角色 |
| DS-09 | 能力关闭 | AI/直播/媒体 Provider 未配置 | 进入能力页 | 显示关闭原因与替代入口，不显示虚假成功 |
| DS-10 | OpenIM 无凭证 | `/auth/im-token` 缺少 token | 打开聊天/直播 | 业务历史仍可读；实时通道降级；不触发 `Go is not defined` |

## 6. 跨端业务闭环

### BC-01 预约—履约—评价—结算

前置条件：信众、寺院管理员、法师、平台管理员四个专用验收账号；寺院与法师已认证；服务已上架且有可用时段；模拟支付渠道明确启用。

1. 信众 H5 选择寺院/法师、服务、日期、时段和功德金并提交。
2. 校验服务端返回的服务费、功德金、总价和支付单号，完成模拟支付。
3. 寺院管理台从“待确认预约”进入详情并确认。
4. 法师 H5 在预约详情依次执行开始、完成。
5. 信众 H5 提交评价，确认防重复评价。
6. 平台管理台查看对应寺院/法师结算与操作记录。

期望：状态依次为 `pending_payment → pending → confirmed → in_progress → completed/reviewed`；每端只出现当前角色允许的动作；费用快照不因后续配置变化而改变；取消/评价/履约动作可审计。

当前状态：L2 页面与状态表达已覆盖；L4 待 ECS 受控写入验收。

### BC-02 DIY—制作—加持—物流—收货

前置条件：DIY 材料有库存；加持服务已启用；商城、寺院和法师账号可用；收货地址为测试地址。

1. 信众 H5 编辑并保存设计，提交下单可用性校验。
2. 按服务端 BOM 和价格创建 DIY 订单并完成模拟支付。
3. 商城管理台审核并更新制作为可分配状态。
4. 寺院管理台分配执行法师。
5. 法师 H5 接单、开始、上传凭证并完成。
6. 商城管理台发货并填写物流；信众确认收货。
7. 平台查看结算和异常审计记录。

期望：材料下架/库存不足时禁止下单并逐项说明；订单保留设计、BOM 和价格快照；凭证在允许状态上传；各端时间线顺序一致；确认收货后不可重复执行。

当前状态：L2 详情、移动任务卡与凭证入口已覆盖；L4 待 ECS 受控写入验收。

### BC-03 内容发布—审核—展示—下架

前置条件：法师具备内容发布权限；媒体 Provider 已配置或明确处于关闭态；平台审核账号可用。

1. 法师 H5 创建图文或视频内容。
2. 平台审核中心查看素材和风险提示，执行通过或驳回。
3. 信众 H5 在大师广场查看已通过内容，完成点赞、关注和评论。
4. 平台下架内容，再次刷新信众端。

期望：待审核内容不对其他信众公开；驳回原因回到法师端；评论遵循先审后显；下架后公开列表不可见但审计记录保留；媒体关闭时呈现能力关闭而非上传成功。

当前状态：L2 内容页、审核页、空态和失败态已覆盖；L4 待 ECS 与媒体能力联调。

### BC-04 即时咨询—双端聊天—权益到期

前置条件：信众与法师验收账号；已支付即时咨询或有效预约；OpenIM API/WSS、`openIM.wasm`、`sql-wasm.wasm` 可达。

1. 信众购买即时咨询或完成预约支付，进入生成的业务会话。
2. 信众发送一条唯一文本，法师端收到并回复另一条唯一文本。
3. 两端刷新页面，确认业务消息历史仍存在。
4. 将权益置为到期/取消/退款状态，再尝试发送。

期望：业务消息服务是历史权威源；OpenIM 只负责实时唤醒；WSS 断线时仍可通过业务服务发送并轮询刷新；权益到期后历史可读但禁止发送；两端无 `Go is not defined`。

当前状态：L2 已验证凭证缺失降级与 WASM 加载顺序；L4 双向真实发送待授权。

### BC-05 售后—商城处理—平台审计

前置条件：一笔允许售后的已支付订单；信众、商城、平台验收账号。

1. 信众提交售后原因和证明材料。
2. 商城管理台在移动/桌面列表进入详情，审核通过或驳回。
3. 若通过，确认退款进度和订单状态；若驳回，确认原因返回信众端。
4. 平台管理台按订单号查询退款与审计记录。

期望：售后状态在三端一致；高风险动作二次确认；金额不由前端自行计算；重复处理被服务端拒绝且页面保留当前数据；操作人、时间、原因和前后状态可追踪。

当前状态：L2 商城退货列表/详情和平台审计入口已覆盖；L4 待 ECS 受控写入验收。

## 7. ECS 发布门禁与回滚

发布前必须同时满足：

- [x] 四个 Web 工程生产构建通过，`git diff --check` 通过。
- [x] 完整 Playwright 目标矩阵通过，失败截图和 trace 已清理或归档。
- [x] 明确 ECS 目标主机、Nginx 根目录、当前版本软链和健康检查 URL。
- [ ] 获得将验收账号凭证发送到 ECS 的明确授权；仅使用专用测试账号。
- [x] 创建不可变版本目录，不直接覆盖当前版本。
- [x] 切换软链前记录旧版本；切换后检查五端登录页、静态资源、SPA 回退和 `/api` 代理。
- [x] 验证 H5 `/c/login`、`/m/login` 以及三个管理台入口。
- [ ] 失败时恢复旧软链并重新加载 Nginx，不回滚数据库业务数据。

发布记录至少包含：构建提交/工作区摘要、版本目录、切换时间、旧版本、健康检查结果、L3/L4 用例结果、回滚命令和执行人。
