# DIY 手串全流程能力审计

> 核对日期：2026-09-03
> 范围：C 端 iOS、C 端 H5、商城管理台、平台管理台、寺院管理台、法师端及 diy/payment/logistics/audit 服务

## 1. 当前产品形态

H5 的 DIY 首页包含公开设计广场和我的设计；编辑器从后台材料目录动态读取珠子与配件，支持分类、五行、关键词、库存筛选，使用 React Konva 进行 2D 有序串珠编辑，并按需加载 Three.js 3D 预览。用户可调整腕围、松紧余量、线材和珠位，执行增加、删除、复制、拖动换位、撤销、重做和清空。

iOS 使用 SwiftUI 原生环形串珠编辑，读取同一材料、SKU、库存、价格和渲染属性，支持分类、关键词、腕围、线材、珠位编辑、撤销与重做。当前 iOS 是带动画和材质效果的 2.5D 表现，没有接入 SceneKit/RealityKit，因此不能写成“iOS 已有真实 3D 预览”。

两端结算都显示设计、材料明细、地址、可选加持、展示预估与服务端最终计价；下单时后端重新查询材料/SKU、上下架、库存和价格，并保存不可变设计与计价快照，客户端单价不可信。

## 2. 能力矩阵

| 能力 | H5 | iOS | 后台/后端 | 结论 |
|---|---|---|---|---|
| 后台维护材料、样式、SKU、库存、价格 | 动态读取 | 动态读取 | 商城管理台 + diy-service | 已具备 |
| 分类/关键词筛选 | 已有 | 已有 | 材料接口 | 已具备 |
| 五行筛选 | 已有 | 未提供独立筛选控件 | 材料含 `fiveElements` | 部分对齐 |
| 2D/2.5D 编辑与动画 | React Konva 2D | SwiftUI 2.5D | v2 有序设计文档 | 已具备 |
| 3D 预览 | Three.js 按需加载 | 无真实 3D | 无服务端依赖 | iOS 缺失 |
| 保存设计/设计详情/广场下单 | 已有 | 已有 | diy_design + 平台设计审核 | 已具备 |
| 下单预览、地址、加持、服务端重定价 | 已有 | 已有 | 库存事务 + 不可变快照 | 已具备 |

| 完整历史订单详情入口 | 列表卡片不可进入完整售后详情 | 主要覆盖当次支付结果 | 有详情接口但导航不完整 | 缺失 |

## 3. 当前可验收闭环

当前能够验收的是：后台上架材料/SKU → H5/iOS 动态选珠 → 2D/2.5D 编辑（H5 可切 3D）→ 保存设计/广场审核 → 地址与加持选择 → 服务端重定价和扣库存 → mock 支付 → 商城审核制作 → 寺院分配 → 法师上传加持凭证 → 商城发货 → 物流签收自动完成。

这不是完整零售售后闭环。要达到“筛选、2D/3D、预览、下单、定制、审批、发货、收货、退货、退款全套流程”，还需依次补齐：iOS 真实 3D 与五行筛选、两端 DIY 订单中心和详情、用户确认收货、DIY 售后单/退货物流/退款及库存和作者收益冲销、商城售后审核，以及对应报表和回归脚本。
