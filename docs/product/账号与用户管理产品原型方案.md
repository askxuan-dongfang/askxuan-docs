## 1. 目标与对象关系

让平台能回答三个问题：这个人用哪个账号登录、代表哪个业务主体工作、为什么现在能或不能访问；让信众消费统计能与实际收款、退款核对。账号停用立即影响后续受保护请求，解封后重新登录；资料、历史订单和资产保留。

| 对象 | 表达的事实 | 本轮边界 |
| --- | --- | --- |
| 信众用户 | 消费者个人资料、登录状态、本人认证资料、真实消费 | 与工作账号分别管理；用户 ID 相同或邮箱相同都不自动合并 |
| 工作账号 | 登录名、显示名称、角色、权限范围、登录开关、业务绑定 | 绑定已有寺院、师傅或商城；创建档案不自动创建登录账号 |
| 业务主体 | 寺院/师傅资料、认证、前台展示和平台经营资格 | 主体可在没有登录账号时独立存在；停用账号不删除主体 |
| 邮箱身份 | 本人已验证邮箱、验证时间及密码找回资格 | 邀请邮箱与本人已验证邮箱分列；历史密码账号不伪称邮箱已验证 |
| 分配记录 | 寺院为本寺纳管师傅分配账号，以及本人激活、寺院停用/恢复 | 分配成功不等于本人激活，也不等于平台允许登录 |
| 会话 | 某次登录及其账号、角色版本 | 撤销会话不改密码、角色、余额或订单；不提供查看令牌的管理页面 |

入口关系为：机构与人员 → 信众列表/详情、寺院/师傅详情；系统与权限 → 工作账号列表/详情。寺院/师傅详情内的“关联工作账号”可反查账号，账号详情内可返回主体。所有跳转保留原作用域，链接本身不能授予权限。

## 2. 角色、作用域与权限

| 身份 | 可见与可操作范围 |
| --- | --- |
| 超级管理员 `platform_super` | 管理工作账号、角色和绑定；查看账号登录原因；平台停用/解除停用、撤销全部会话；按原权限管理信众及主体 |
| 自定义平台岗位 | 仅使用明确委派的权限。信众查看/管理分别为 `platform.users.read/write`；寺院查看/运营状态分别为 `platform.temples.read/write`。账号、角色和认证审核不因有平台入口而自动开放 |
| 寺院管理员 `temple_admin` | 统一管理本寺资料、人员、服务、排班、履约和财务；寺院端不提供管理岗位子账号；为本寺已认证纳管师傅分配、停用或恢复账号；不能解除平台停用或管理其他寺院账号 |
| 师傅 `master` | 本人工作台及原有业务权限；纳管师傅还受父寺院认证/平台状态约束；不能取得总平台账号管理权限 |
| 商城运营 `shop_admin` | 已绑定商城及显式授权的商城工作；不默认获得平台信众、账号或认证管理权限 |
| 入驻申请人 | 仅申请、补材料及既有申请查询范围；审核通过前不能靠切换账号状态进入正式工作台 |
| 信众 `customer` | 本人消费和个人业务；无后台用户管理权限 |
| 内部服务身份 `platform_service` | 不提供人工登录、人工刷新或人工工作会话；不能把内部身份当成普通运营岗位 |

工作账号管理使用超级管理员专属 `super.security`，不是本轮可委派能力。最后一个有效超级管理员受服务端保护，不能通过停用、角色修改等操作移除最后的管理入口。前端隐藏按钮与后端逐请求鉴权同时生效；寺院状态敏感写入还向固定认证服务核验真实会话，不信任客户端伪造身份头。

## 3. 页面文字原型

### P01 信众列表 `/admin/user/list`

顶部为标题、刷新；筛选区为手机号/昵称、正常/封禁、查询、重置。列表依次展示头像与昵称、用户 ID、脱敏手机号、地区、已付订单、净消费、状态、注册时间及操作。底部使用真实总数分页，单页上限 100。

| 动作 / 区域 | 行为与反馈 |
| --- | --- |
| 详情 | 进入 P02；不跳到同邮箱的工作账号 |
| 封禁/解封 | 明确确认；提示旧会话失效、资料和资产保留，解封仍需重新登录。成功后回读列表 |
| 统计说明 | 固定说明“真实渠道已付款订单，实付减成功退款；不含模拟付款、体验订单和测试余额” |
| 加载/失败/无结果 | 加载不填假零；统计或列表失败显示“用户与消费统计加载失败”及重试，不能解释为无用户或零消费；成功零结果保留筛选条件 |

查看和状态写入分别按读/写权限核验；只读岗位即使构造状态请求也不能执行写入。

### P02 信众详情 `/admin/user/detail/:id`

1. 资料区：头像、昵称、状态、用户 ID、脱敏手机号、性别、生日、地区和简介。
2. 统计区：已付订单、净消费、最近活跃、偏好标签数量，附消费口径和服务端统计时间。
3. 登录身份区：凭据状态、本人邮箱、已验证/未验证、验证时间、找回方式说明。
4. 偏好区：实际偏好标签；成功读取后无标签显示“暂无偏好标签”。

详情、认证或统计缺失/读取失败时显示错误和重新加载，不把未完整返回的对象拼成空资料。原有用户画像只承担偏好和活跃信息，不再为订单数、消费额提供过期缓存值。本页不新增代用户重置密码、合并身份或手改消费的动作。

### P03 工作账号列表 `/admin/settings/account`

顶部为新建、刷新；筛选区为账号/姓名、启用/停用、角色、查询、重置。表格展示登录账号、名称、角色、所属主体、账号状态及“平台停用”标记、最近登录、详情/编辑/平台停用或解除平台停用。小屏工作账号使用卡片承接同一字段和操作。

从主体进入时带 `templeId` 或 `masterId`，顶部提示“当前仅查看此业务主体关联账号”，提供“查看全部账号”；查询不会悄悄丢弃主体过滤。后端还支持 `roleId`、`shopId` 等明确条件，非法数字或状态拒绝，分页上限 100。没有在 UI 中提供的筛选不冒充已有入口。

新建表单为登录账号、初始密码、显示名称、角色及该角色所需主体；编辑只修改显示名称、角色和绑定，登录名不可编辑，也不通过普通编辑重放旧的启停状态。切换角色清理不适用绑定：寺院管理员必须选寺院；师傅必须选明确师傅，寺院归属从师傅档案核验；商城必须有商城标识；平台角色不夹带机构绑定。

主体/角色辅助目录失败与账号列表失败分开提示；名称不全不等于主体不存在。取消关闭表单；保存中防重，失败不显示成功。角色或绑定改变后原会话失效，不能继续使用旧身份权限。

### P04 工作账号详情 `/admin/settings/accounts/:id`

| 页面区块 | 字段 / 动作 |
| --- | --- |
| 账号与访问 | 名称、登录账号、ID、启用/停用、平台停用标记、角色、权限范围、注册时间、最近登录；明显展示“允许登录/当前不可登录”及全部原因 |
| 主要动作 | 平台停用/解除平台停用、撤销全部会话、编辑角色与归属、刷新、回账号列表 |
| 认证与激活 | 凭据状态、本人邮箱及验证状态、验证时间、邀请邮箱、待本人激活/已激活/已停用分配状态、密码找回说明 |
| 业务身份关联 | 寺院/师傅/商城类型、编号、名称及各自认证/上架/平台状态；寺院、师傅提供“查看主体” |

“撤销全部会话”确认说明：所有已登录端退出，账号状态和密码不变，本人满足资格后可重新登录。撤销操作者自己的会话时，下一次受保护读取进入登录失效流程，不再将返回登录误报为详情加载失败。

读取失败或字段结构不完整时不显示“允许登录”；切换详情编号后旧请求不能覆盖新账号。平台角色没有业务绑定时显示“不归属寺院、大师或商铺”；已配置但主体不存在则保留编号、标记缺失并说明原因，不与“无绑定”混淆。商城关联当前只展示已配置标识，不虚构商城主体详情。

### P05 主体详情内“关联工作账号”

寺院和师傅详情向超级管理员展示账号名称、登录名、角色、启停状态、账号详情及“管理关联账号”。先显示前 20 条，更多进入带主体条件的 P03。无账号时说明“业务资料可独立存在，创建档案不会自动生成登录账号”；读取失败显示“不能确认当前是否已有账号”，不能鼓励重复创建。

### P06 寺院“大师账号分配”

本寺管理员选择本寺已认证纳管师傅，填写本人邮箱和唯一登录用户名后分配。成功提示本人去大师端“寺院分配账号激活”，验证邀请邮箱并设置密码；不向管理员提供大师的密码。用户名保持既有 4–32 位小写字母、数字或下划线规则。

已分配列表分别展示大师编号、用户名、激活邮箱、激活状态、账号状态和平台停用提示。寺院停用使已有会话失效，保留大师档案和订单；恢复仅处理寺院分配，未激活仍须本人激活。平台已停用时，寺院恢复按钮禁用并明确“请联系平台核对”；激活/恢复接口同样拒绝绕过平台标记。读取失败提供重试，不把失败列表当作无分配记录。

## 4. 账号生命周期与登录原因

| 事实 / 操作 | 规则 |
| --- | --- |
| 账号启停 `status` | `enabled/disabled` 表达当前账号开关；不是认证、前台上架或邀请激活的代名词 |
| 平台停用 `platformDisabled` | 平台停用将账号置停用并记录独立平台标记。本人激活、寺院恢复、普通资料编辑不能清除这个标记 |
| 解除平台停用 | 只由平台处理；待本人激活或寺院已撤销的分配仍保持停用。关联资格不符不能靠启用通过审核；旧访问、刷新会话都不恢复 |
| 本人激活 | 分配记录为待激活时，由本人验证邮箱并设置密码；平台停用、主体资格不符则拒绝激活 |
| 寺院停用/恢复分配 | 只针对本寺纳管师傅；撤销分配与平台停用分别保留，互相不覆盖 |
| 撤销全部会话 | 递增权威账号版本；不改账号状态、密码或业务主体。后续需要本人重新登录 |
| 信众封禁/解封 | 状态真实变化时与版本递增原子提交；同值请求不重复递增。解封允许新登录，不允许旧会话复活 |

详情按实际数据累积登录原因：待本人激活、寺院已停用分配、平台已停用、工作账号已停用、无可用登录凭据、主体未关联或不存在、主体未认证/被封禁、账号与师傅寺院归属不一致、内部服务身份不供人工登录。一次可以出现多个原因，不能只展示一个笼统“异常”。该判断是读取时点的状态说明，真正登录和每次受保护访问仍重新核验。

凭据展示区分：已验证邮箱、原有密码账号、待本人激活、认证资料待核对。只有有效已验证本人邮箱才提示可通过登录页找回；邀请邮箱、历史占位邮箱或无验证记录不能作为已验证邮箱展示。管理页面不返回密码、哈希、访问令牌或刷新令牌。

## 5. 寺院四维状态及关联业务

寺院列表/详情展示“认证与运营状态”，分别管理以下四个维度，`stateVersion` 仅用于防止覆盖并发修改。

| 维度 | 值 / 管理来源 | 界面及业务含义 |
| --- | --- | --- |
| 认证 | `pending/certified/legacy_unknown`；认证审核流程 | 待审核、已认证、历史认证待核对；运营状态操作不能把未审核寺院改成已认证 |
| 平台资格 | `normal/banned`；平台管理状态 | 平台正常/封禁。封禁强制寺院下架，使关联工作身份不可访问，并停止新发现、新咨询/预约及新付款 |
| 前台上架 | `on_shelf/off_shelf`；运营管理状态 | 仅已认证、平台正常方可上架。下架隐藏公开列表、公开详情和寺院服务，后台资料和历史履约保留 |
| 推荐 | `true/false`；独立推荐动作 | 只改变推荐标记，不通过审核、不解除封禁、不自动上架 |

状态操作为上架/下架、设为/取消推荐、封禁/解除封禁，每次先解释影响再确认。提交携带当前版本；成功回读权威结果。旧版本返回 `40901`，提示状态已变化、刷新后重试，不自动覆盖他人修改；空更新、非法枚举拒绝。版本资料不全或写入失败时停止继续操作，待刷新确认。同值操作不推进版本。

封禁和解封都会使关联工作账号版本失效；解封仍保持寺院下架，核对认证后另行上架。终审只更新认证事实并推进版本，不清平台封禁，也不暗改前台上架。旧“正常/推荐/封禁”状态保留为兼容投影；旧状态入口也不能绕过认证。常规资料保存不回写旧的运营状态。

父寺院未认证或被封禁，其下师傅不能新发现、新咨询或新预约；师傅资料和原订单展示仍保留。父寺院只下架时，不永久改写师傅自身上架开关，已上架且合格的师傅可保留独立咨询。新支付对原订单寺院快照及师傅现归属资格重新校验；认证不合格/封禁拒绝扣款，单纯下架允许既有订单按原价格继续结算和履约。已付款重试只返回原结果，不重复收款。

## 6. 真实消费统计口径

统计标识为 `real_paid_net_refunds`，以权威支付、成功退款记录为准；按服务端读取时间返回 `statsUpdatedAt`。列表和详情使用相同规则，不把用户画像的历史汇总相加。

| 项目 | 当前算法 / 范围 |
| --- | --- |
| 业务类型 | 预约 `booking`、即时咨询 `consultation`、商城 `shop_order`、DIY `diy_order`、人民币 AI 报告 `ai_report` |
| 实收范围 | `wechat/alipay/balance`，金额大于零，支付为成功、退款中或已退款；不因列有渠道编码便宣称外部渠道已接通 |
| 已付订单 | 按业务类型 + 业务单号去重；有退款历史仍是曾付款订单，不退回为未付订单 |
| 净消费 | 每笔真实支付金额减该笔成功退款，最低为零；已全额退款支付贡献零。处理中/失败退款不提前扣减 |
| 异常多次收款 | 同一业务单实际多次成功入账仍计入实际金额，但业务订单只计一次；不以去重掩盖异常实收 |
| 排除 | 模拟 `mock`、测试余额 `demo_balance`、`EXO-` 体验订单、充值、积分付款、待支付及失败支付 |
| 金额单位 | 数据汇总全程整数分，API 转为元，界面人民币两位小数；退款按支付记录先聚合，避免多退款连接放大金额 |

无符合条件的支付才是零；支付/退款读取失败返回统计不可用，不伪造零。当前真实余额退款仍只支持整单退款，本轮统计支持成功退款记录聚合，不等于新增了部分退款业务入口。

## 7. 全端登录反馈与页面一致性

| 返回 / 场景 | 产品反馈与会话行为 |
| --- | --- |
| `40105` 旧会话被撤销 | 信众/工作账号一致：清理当前失效登录状态，回登录或显示需重新登录；不使用旧刷新令牌反复续期，不恢复旧权限 |
| 普通令牌过期 | 按既有刷新流程最多恢复一次，并发请求合并刷新；无法恢复再退出。刷新不能覆盖用户后来完成的新登录 |
| `50205` 身份依赖暂不可用 | 拒绝本次受保护操作并显示稍后重试；不能冒充账号封禁、数据为空或操作成功。普通接口收到该码不按会话撤销处理 |
| `403xx` 权限不足/资格不符 | 展示无权限或具体资格原因；不把权限拒绝当成令牌过期，不反复刷新有效会话 |
| `40901` 状态版本冲突 | 保留已知信息为只读，要求刷新后确认；不自动重放状态写入 |
| 切换账号/登出 | 清理本人数据、权限和旧请求归属；前一个账号的迟到响应不得写回新账号页面 |

管理 Web 与寺院 Web 共享会话恢复规则；Mac 门户承载对应真实 Web 工作台，业务权限由相同接口核验。信众/师傅 H5、双 iOS 及原生内嵌内容保持相同撤销码含义，原生登录与内嵌会话不能各自悄悄恢复已撤销身份。跨端统一的是状态、权限、错误和数据合同，不要求信众端出现后台账号管理表格。

沿用全局字体、主题和简繁文案；状态有文字而非只用颜色，确认操作与读取错误可被读屏识别。账号详情小屏按单列重排、邮箱和编号允许换行；加载、无数据、无权限、不可确认四种状态分开表达。

## 8. 数据迁移与回滚边界

采用增量字段和最小读写权限：信众持久会话版本、寺院认证/平台/上架/推荐/版本、工作账号平台停用标记；消费统计只读支付、退款和本人邮箱投影。保持原账号 ID、主体编码、密码、角色绑定及账本，不重新创建或按邮箱合并用户。

旧寺院“正常/推荐”映射已认证且原有上架，推荐标记单列；旧封禁保留封禁和下架，认证标记 `legacy_unknown`，不能因解封自动认证；其余旧审核状态保持待审核。旧停用工作账号无法可靠追溯是平台还是寺院所停时，保守记录平台停用，需明确平台处理后再走本人激活/寺院恢复；迁移不批量解禁。

发布前核对实际数据库结构、账号、权限和配置，备份后执行迁移；先具备新字段与最小权限，再发布读取新合同的服务和客户端。已有列的脚本按其重入约定处理；一次性寺院映射不能当作日常同步反复覆盖运营决定。

回滚优先暂停相关状态写入、保留数据并修复或回到兼容新字段的版本；前端回退不撤销已提交的业务状态。不能把不理解持久版本/平台标记的旧鉴权服务直接当作安全回滚版本，否则可能重新接受已撤销会话。保留新增字段、历史版本与审计，不回减会话版本，不恢复旧令牌，不通过恢复旧库覆盖新订单/退款。具体备份、制品和发布结果以验收报告记载为准。
