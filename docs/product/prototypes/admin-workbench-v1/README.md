# 管理平台原型 v1

[产品架构与页面合同](../../管理平台产品架构与原型方案.md) · [业务模型与迁移](../../管理平台业务模型与迁移约定.md) · [验收记录](../../../reports/2026-10-21-管理平台产品架构与原型.md)

从 docs 仓库根目录执行 `python3 -m http.server 4297 --bind 127.0.0.1`，打开 `http://127.0.0.1:4297/docs/product/prototypes/admin-workbench-v1/`。原型使用浏览器模块，需要通过本地 HTTP 访问。

建议按以下顺序评审：

1. 工作台 → 机构与人员，分别选择民间信仰 / 妈祖、关帝，查看同一对象的多信俗关联。
2. 叠加台湾地区形成零结果，检查条件与标准选项仍保留；清除后翻页。
3. 打开澄和宫，修改名称或服务，在“验收演练”模拟资料成功 / 服务超时，仅重试服务。模拟他人更新后核对版本；尝试带草稿离开并取消。
4. 基础标准 → 宗派与信俗，查看编码只读、引用影响，调整展示名或停用；返回列表检查显式条件与新名搜索。
5. 审核与治理，验证寺院初审通过只进入终审；退回资质时填写原因，不改变入驻队列。
6. 商城与 DIY → DIY 订单，确认已付订单的款式、用料和价格，只形成发布资格。
7. 内容与 AI，预览首页入口文案后发布示例；系统与权限查看对象操作记录。切换寺院、师傅、商城视角检查范围差异。

所有提供者、订单、审核、金额和操作均为虚构内存示例。24 项宗派和五类 / 七心愿 / 十三服务沿用既定目录语义，不是穷尽式宗教学分类。刷新会重置记录，不请求业务接口、不保存登录或浏览器用户数据。角色切换不等于真实授权，财务、AI 及其余履约仅为导航与规则示意。

模型回归：`node scripts/check-admin-workbench-prototype.mjs`。实际浏览器、生产接口、权限、原生和数据迁移验收必须分别记录。
