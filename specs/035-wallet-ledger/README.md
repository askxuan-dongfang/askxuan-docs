# 钱包：账单与结算首期

## 产品边界

信众在“我的钱包”集中查看支付账单、退款进度和原订单；大师在“我的钱包”查看本人结算份额；寺院在管理台的钱包查看本寺院结算。寺院纳管大师只按本人大师 ID 归集，不把寺院订单总额计入其收益。

本期只读现有支付、退款、结算和提现记录，不创建充值余额，不开放充值、转账、余额支付或真实提现。积分和功德成长保持独立。演示支付单独筛选；历史模拟提现明确标注，结算状态不能充当银行到账证明。

## 实现

- 客户接口 GET /payments/wallet：JWT customer，仅本人，mode=channel/mock、filter=all/refunds、page；以分为单位，汇总不受分页影响。
- 服务方接口 GET /finance/wallet/master 或 temple：服务端 JWT 角色及身份归属校验，忽略客户端传入的归属 ID。
- H5、原生双 iOS 和寺院管理台统一入口、可展开明细、分页、空态、错误重试。保留 iOS 原生导航手势。
- 无表结构或业务数据迁移；财务账号新增大师表 id/code 两列的只读授权，不改变既有订单详情和会计账本。

## 验收

- 两个客户、两个大师/寺院互不可见；伪造 query/header 无法更改归属。
- 多次部分退款不放大消费汇总；失败退款不计已退，处理中单独统计，金额按分精确。
- 演示与渠道记录分开；失败不显示为零资产；刷新/切换账户不展示旧账户数据。
- API 单元及隔离 MySQL 测试，前端构建与浏览器验收，双 iOS 可构建验证。

## 交付

实现已完成，双 iOS 编译、本机及 CI 回归通过。ECS 后端、H5、寺院管理台已发布，信众及寺院页面线上验收通过；大师钱包因生产财务账号缺少身份映射查询权限而尚未通过。最小授权脚本与受限账号回归已提交，生产执行等待明确授权。充值、真实提现和支付渠道接入为后续独立阶段。
