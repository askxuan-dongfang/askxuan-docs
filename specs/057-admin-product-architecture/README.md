# 管理平台产品架构与原型

> **Status**: ⏳ In progress · **Priority**: High · **Created**: 2026-10-21 · **Tags**: admin, product, prototype

## Overview

管理平台目前把标准分类、提供者资料文本、筛选关联和首页展示配置分散维护。部分资料保存跨两个请求，存在资料成功而服务失败的风险。先交付业务模型、完整信息架构与可操作原型，再分阶段修改生产系统。

本规格继承 [028 统一后台](../028-unified-admin-consolidation/README.md)：商城属于平台后台，寺院台独立。设计交付不等于实际重构完成，整体保持进行中。

## Design

- 九个工作区：工作台、机构与人员、服务与履约、商城与 DIY、审核与治理、财务与权益、内容与 AI、基础标准、系统与权限。旧地址、详情与兼容入口保留。
- 基础标准唯一维护；五类、七心愿、十三服务沿用既定编码；保留多信俗及历史跨类关联、身份擅长资料、旧 sect/region 文本。地区显式覆盖与继承分别呈现。
- 提供者详情解释标准归属、展示资料和实际服务；分段保存，成功失败分别反馈，仅重试失败段。版本冲突先对比，保留草稿。原型演练不证明现有 API 支持版本协议。
- 入驻、寺院初终审、师傅资质各自保持状态与副作用；订单只统一入口，不合并服务、咨询、商城、DIY、积分状态机或账本。
- 平台 / 寺院 / 师傅 / 商城职责及作用域保留，导航重组不扩权。新能力矩阵须先定接口合同。
- DIY 付款及款式、用料、价格确认后才具发布资格；公开版本和历史成交快照保留。成长、积分、现金与奖励分别记账。

## Test

- 原型：多信俗与零结果筛选、地区继承 / 覆盖、部分成功 / 重试、并发草稿、标准更名 / 停用、审核分阶段和 DIY 定稿资格。
- 实施：平台三角色及寺院 / 师傅范围的读写正反向验证；真实 API、H5、原生、寺院台回读一致；旧书签与历史交易不变。
- 迁移：前后标准及关联数量 / 摘要、历史跨类关系、地区继承、心愿继承 / 显式空选和恢复演练；不可把差异自动判错或整库覆盖新订单。
- 源码、内存原型、浏览器、Git、部署和生产数据分别留证。详见[本轮方案验收记录](../../docs/reports/2026-10-21-管理平台产品架构与原型.md)。

## Notes

本轮不修改生产系统，不执行数据清理、不新增角色权限，不新增顶层分类、心愿或服务。财务与 AI 仅交付导航和规则示意，未形成完整业务原型或真实交易验收。
