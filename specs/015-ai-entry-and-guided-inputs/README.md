# AI 问事入口收敛与专题资料引导

> **Status**: ✅ Complete · **Priority**: Medium · **Created**: 2026-09-10


## 问题与体验决定

专题卡片、同名技能筛选和输入框上方“已选”重复呈现同一组术数，用户难以理解报告与聊天的区别。H5 和 iOS 收敛为直接问事 + 一套七专题入口：日常问题直接输入，系统化解读进入专题补充资料、生成摘要、按积分价格解锁。既有专业会话、报告追问、删除确认与重试保持可用。

首页新会话明确使用 `general`；不强制用户选择术数，不悄悄切换到缺少排盘资料的自动路由。专题填写页是唯一结构化资料入口。H5 延续全站暖棕/金色与共享字体，采用带说明的选项卡片、条件展开、聚焦边框、轻量进场；支持键盘操作和减少动态效果。iOS 同步条件选择与原生时间选择器。

## 真实字段与填写说明

已核对生产 `/api/v1/ai/skills`、ai-service 参数适配器、技能源文件和部署中 MCP 的 `tools/list`。技能文件是设计来源，不代表其所有能力均已集成。

| 专题 | 用户填写 | 实际接入与限制 |
| --- | --- | --- |
| 八字 | 生日、出生时分、历法、性别、出生城市 | MCP `bazi`；年份 1900–2100。农历按年月日填写，支持非公历合法日如农历二月三十；闰月当前需换算公历，未知出生时间不猜测 |
| 紫微 | 同上 | MCP `ziwei`；城市作为解读背景，当前适配器不将其作为经纬度校正输入 |
| 姻缘 | 个人或双方模式，生日选填，下一步补充关系背景 | 当前未启用 MCP 合盘工具；仅双方模式显示对方生日 |
| 塔罗 | 单牌、三牌、爱情或抉择牌阵 | MCP `tarot`，后台完成实际抽牌；不是点击插画决定牌面 |
| 风水 | 住宅/办公/商铺，城市与朝向选填，下一步说明布局与困扰 | 当前以描述解读，无专用 MCP 测量；不知道朝向可留空 |
| 奇门 | 问事时间、所在城市，下一步问题与目标 | MCP `qimen`；北京时间 UTC+8，使用既有转盘/拆补/寄六仪配置；技能文档中的其他派别并未自动接入 |
| 六爻 | 起卦方式 + 关注事项 | MCP `liuyao`，与服务中的 `meihua` 为不同工具。自动方式无需数字或时间；数字方式需要 2–3 个 0–999999 的整数；时间方式需要北京时间 |

关注事项保持后台值：官鬼（工作/职责）、妻财（收入/资源）、子孙（成果/状态）、父母（学习/文书/长辈）、兄弟（合作/竞争）。卡片增加通俗解释，问题细节在下一步填写。自动和数字起卦由后台提供提交时刻；“使用当前北京时间”按 UTC+8 生成，与浏览器或手机所在时区无关。

## 实现边界

- 后端 `agent/inputguide.go` 为已配置字段补充 `helpText`、选项说明、有效默认值、`visibleWhen`、`requiredWhen` 和数字校验标记。保留后台字段、选项值和未知元数据，不新增后台未开放的选项。两端消费同一份说明。
- H5 `AiGuidedFields.tsx` 与 iOS `AiSkillField` 根据条件展示/校验；切换方式会清除隐藏字段，提交仅携带可见且非空的字段。
- 报告在额度获取及创建记录之前校验条件必填与工具参数。数字输入不再截断第 4 个数字、忽略负号/小数或吞掉溢出。MCP `isError` 不再作为正常排盘事实写入报告。
- 农历生日不经过公历日期转换，避免二月三十被拒绝或篡改；实际历法有效性最终由对应排盘引擎判定。
- 摘要/解锁的幂等请求、积分扣费规则与历史数据不变。本次无数据库迁移。
