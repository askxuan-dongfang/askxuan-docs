# 简易商城选购流程

> **Status**: ✅ Complete · **Priority**: Medium · **Created**: 2026-09-10


## 目标

在 [上一轮商城设计](../016-storefront-experience/README.md) 基础上，参考常见电商的搜索、分类、商品网格、规格弹层与勾选结算结构。保留问玄东方的棕金配色及统一字体，压缩装饰区域，让商品更早进入首屏。

## 顾客体验

| 页面 | 变化 |
| --- | --- |
| H5 商城首页 | 顶部搜索与购物车；积分商城、DIY、普通订单、定制进度快捷入口；真实分类、价格排序、有货筛选；紧凑双列商品卡 |
| 商品详情 | 主图滑动和缩略图、价格与名称优先、规格摘要；加入购物车和立即购买均打开底部规格弹层 |
| 购物车 | 单选/全选、数量调整、移除、所选数量和金额；结算只包含所选商品 |
| 确认订单 | 独立步骤展示地址、本次商品、备注及费用；直接购买不加入或清空购物车 |
| 订单列表 | 待付款/待发货/待收货/已完成/售后/取消筛选；根据真实状态显示付款、物流、售后操作，不再固定显示支付成功 |
| iOS | 同步紧凑搜索分类布局、等高商品图片、规格弹层、立即购买、勾选购物车与订单确认快照 |

H5 规格弹层使用原生 modal dialog，包含标题、关闭、焦点约束、Escape 退出、背景滚动锁定与减弱动态效果支持。图片失败有明确占位；筛选参数和分页行为沿用服务端契约。

## 交易约束

- 正式商品与服务端价格/库存校验保持不变，不新增优惠、销量或评价等虚构信息。
- 下单前重新读取商品与 SKU；未上架、缺货、规格失效或价格变化阻止创建订单。
- H5 结算商品和账户保存在当前导航记录中。准备下单后保存完整请求、requestId 与已创建订单 ID；同一结算页面刷新重试复用原请求。此恢复范围为当前浏览器导航记录，不是跨设备订单草稿同步。
- 创建订单和支付使用服务端返回的订单金额；模拟支付仍明确标识，不暗示真实付款接入。
- 成功后只扣减本次购买的购物车数量，保留未选商品及之后加入的数量。立即购买不改变购物车。
- 账户切换时隔离购物车与结算状态，异步响应不会清空另一个账户的购物车。
- 订单详情的确认收货、退款、退货寄回和物流记录全部保留；积分、活动、功德值逻辑不变。

## 管理平台

仍位于统一管理平台的「商城与权益」。商品编辑预览同步采用搜索、分类提示、主图、名称与价格卡片；完整介绍在详情展示。商品表格、顾客视角、分类排序、标签、上下架、SKU、配送模板、订单与售后管理保留，没有建立第三套后台。
