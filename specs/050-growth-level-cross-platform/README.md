# 五级成长体系：全端体验、发布与验收

> **Status**: ⏳ In progress · **Priority**: High · **Created**: 2026-10-19 · **Tags**: product, growth, cross-platform


> `growth-v1` 首期代码和标准交互原型已实现；后端、H5、运营/寺院Web已发布ECS，原生证据与货币权益开放条件单列。依赖[成长值与等级](../048-growth-level-foundation/README.md)和[权益与结算](../049-growth-level-benefits/README.md)。下文保留完整产品目标；本轮已实现项与尚未验收项见文末记录，不把设计目标当作上线结论。

## 全端统一边界

统一的是同一账号的成长余额、等级、适用权益和订单金额，各角色按职责展示，不给法师/寺院套一套客户等级。

| 端与形态 | 必须覆盖 |
| --- | --- |
| 信众 H5，含移动/桌面浏览器、PWA | 我的、成长中心、商品/服务/报告详情、结算、订单、售后、规则与记录 |
| 信众原生 iOS | 同等业务能力；原生导航、动态字号、VoiceOver；与 H5 同账号同数据 |
| 原生内嵌 H5 | 使用宿主认证与语言，支付后回原页面刷新；不重复领取、计成长或生成报价 |
| 法师 H5/PWA 与原生 iOS | 服务参与状态、订单客户等级快照、本单优惠来源、应结算金额；不展示客户笔记或完整成长流水 |
| 寺院 Web 及 Mac 管理台门户 | 本寺服务参与开关、合同/补贴明细、所属订单及对账；不越权管理客户成长 |
| 统一运营 Web，含商城；Mac 对应门户 | 规则版本、任务、参与商品/服务、预算、成长流水审计、优惠对账、异常补偿 |
| 旧商城入口、东方珠作入口 | 复用正式商城/DIY 规则与订单快照，不形成独立等级账户 |
| 将来的 Android、小程序、其他客户端 | 本期没有独立实现或验收结论；新增形态接入同一契约与验收集，不另设规则 |

客户主体取认证的 customer ID，不按邮箱、手机号或不同角色的相同数字 ID 自动合并。法师执业评分和收入独立；客户身份关联须可信绑定和本人授权，客户端不能指定他人成长账号。

## 用户体验

“我的”头像下显示“L3 笃行 · 成长值 1,250”，独立成长卡显示“距 L4 还差 1,750”、待入账数量及入口。进度为 (当前值−本级门槛)/(下级门槛−本级门槛)，不是累计值直接除下级门槛；L5 显示已达最高等级和累计记录。积分与钱包仍独立。

成长中心包含当前等级/五档权益、可做任务、成长记录、规则四区。每项任务显示数量、资格、剩余次数、到账时点；完成、待审核、待入账、已入账、冲回和异常有明确文字。成长详情能回原订单；入口暂不开放时保留原占位，不能先显示虚构等级或可领取奖励。

游客可以看五级规则及商品参与说明，个人卡显示“登录查看成长等级”，不显示 0、L1 或假的预计收益；登录完成返回来源页并重新取数。网络失败显示“暂时无法读取，重试”，不把旧账号数据或错误当零；退出/换账号清除账号缓存及未确认报价。

商品/服务页区分“我的等级价”“指定项目参与”“不参与原因”；游客仅看到“登录查看可享优惠”，不能以最高等级价冒充人人可买。结算列原销售金额、活动/等级/券减免、运费、随喜、合计、预计成长值和到账规则。命中封顶时写“本单等级优惠已达上限”，不笼统写整单 9.2 折。金额变化需要重新确认。

升级在下次前台轻提示一次，跨级只提示最终等级及新权益；遵循减少动态效果。降级说明对应退款和扣回值，不追补已付差价；不公开排行或鼓励随喜买等级。

## 简繁与外观

界面语言沿用 system / zh-Hans / zh-Hant；只支持简体与繁体，外观偏好独立。语言和主题切换保留路由、表单、登录态与报价有效期，不改币种、业务时区、阈值及倍率；语言偏好仍按现有设备设置，不擅自升级为账号同步。

| 简体 | 繁体 |
| --- | --- |
| 成长值 / 成长等级 / 成长记录 | 成長值 / 成長等級 / 成長記錄 |
| 等级权益 / 等级优惠 / 升级礼券 | 等級權益 / 等級優惠 / 升級禮券 |
| 待入账 / 已入账 / 退款扣回 | 待入帳 / 已入帳 / 退款扣回 |
| 距下一级还差 {n} / 已达最高等级 | 距下一級還差 {n} / 已達最高等級 |
| 登录查看成长等级 / 指定项目参与 | 登入查看成長等級 / 指定項目參與 |

沿用主题 tokens，等级用图标/文案区分，不覆盖用户主题。验收浅深色、键盘、读屏、触控目标与 320px 窄屏，状态不能仅靠颜色。原因码与参数由共享字典显示；用户笔记、历史原文不自动简繁转换。

## 统一契约及管理权限

- 账户快照：customer ID、环境、有效/待入账成长值、等级编码、上下级门槛、下一等级所需值、权益资格、规则版本、数据修订号、更新时间；金额均为整数分，缺数据不是零。
- 账本：事件 ID、来源单据/任务、增减值、状态、冲回关联、发生/入账时间、版本；服务端去重并校验归属。
- 报价：quote ID、原始结算单 ID、失效时间、行价、等级、候选/选中方案、分摊、预算/额度、券、应付、预计成长、排除原因；服务端复验归属与金额，拆子单共享原结算单封顶。
- 付款成功、完成、退款、任务入账均由业务事实驱动；事件可重试、补偿、对账。刷新/重新前台/业务操作完成后更新账号修订号；正常在线时 30 秒内同步，主动刷新读取最新值，不依赖另一端刷新触发记账。
- 发布规则者、预算审批者、补账者分权；人工补账需原事件和原因，双人复核、全程审计，不可直接改总值。提供者只申请/撤回本项目参与，已冻结优惠继续履行。
- 配置按版本保存：阈值、来源/上限、倍率、券、范围、最低贡献、预算、到账期限、时区和开关。先草稿预览、样例核算，再批准和定时生效；用户页可查当前及历史规则。后台报表分开展示成交、补贴、成长发放、退款冲回和提供者结算。

## 接入顺序与发布条件

1. 后端先完成成长账本和五类业务事实映射；接入当前收银前先确认费用分拆、来源及合同字段。尤其不能把旧 `meritMoney` 总项直接视为固定服务费。契约缺口需相关模块确认后补充，不改已有字段含义。
2. 配齐精选内容、活动核销、升级券模板、商品/服务白名单及营销预算；缺失任务入口隐藏，不能显示领取后失败。成长估算必须能追溯到后端实际事件。
3. H5、iOS、两个运营 Web、Mac 与内嵌页消费同一契约。当前已发布旧客户端若无法表达正确应付与权益，必须保持可用的兼容报价或升级提示；未核验前不对这些账号打开货币优惠。
4. 影子核算不产生正式成长或优惠；随后按客户账号灰度，一账号在各端命中一致。正式灰度账本永久保留，回滚不能清零；低版本处理要先验收。
5. 全端业务验收、资金/补贴/券对账及真实支付渠道门槛通过，才撤下“成长记录待开放”。真实渠道未就绪时只能独立演示，不把模拟数据迁入正式账户。
6. 回滚关闭新报价优惠和新任务发放，保留已有账本、已付价格与冻结优惠，继续退款冲回和对账；恢复从原事件重放去重，不追补停发期未承诺的奖励。

| 场景 | 必须结果 |
| --- | --- |
| 五级边界与跨级 | 199/200、999/1000、2999/3000、7999/8000 精确切档；L5 无错误升级进度 |
| 免费来源与月界 | 多端重复任务只发一次，月上限 200；上海月末与海外设备一致 |
| 成长订单 | 六类费用拆分正确；各业务完成+7天入账，接单/付款不提前升级 |
| 退款 | 全退、已支持的部分退款、跨月、重复/乱序回调均只冲正确差额；积分独立 |
| 优惠 | 五档倍率、¥100/¥50 单次和 ¥300 月封顶、分摊尾分、券择优、项目排除一致 |
| 跨端并发 | 两设备抢月剩余额度/同券，只成功占用一次；支付处理中不错误释放 |
| 原单快照 | 下单后升级/改配置不重算；超时明确重新确认；退款不追扣其他已付订单 |
| 提供者/创作者 | 供应方保底与营销预算对账；作者仍按材料实付5%/¥20/7天规则 |
| 角色与数据 | 客户互不可见；大师只见所需快照，寺院/商城不越权；无私密笔记泄漏 |
| 游客与失败 | 无伪造等级/金额；登录回来源；过期、断网、账号切换无残留 |
| 简繁与主题 | 全端 system/简/繁及浅/深/系统外观组合，动态字号/键盘/读屏可用 |
| 灰度与恢复 | 新旧版本、PWA缓存、WebView、Mac门户、iOS真实交互分别留证；不以构建替代业务验收 |
