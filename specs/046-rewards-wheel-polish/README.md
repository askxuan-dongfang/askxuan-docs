# 积分转盘、多奖品与兑换履约

## 目标

保留墨绿、米白与金色，修复转盘失圆及积分活动返回循环。每期转盘配置多种真实奖品，H5 和 iOS 展示同一奖项并停到后端实际抽中项。支持实物、兑换码和独立兑换链接，原有单实物活动及历史订单兼容。

## 设计

- 活动最多 7 种奖品，另设谢谢参与扇区。扇区面积仅用于展示；用户点击转盘中的奖品才展开详情；详情和规则公开每项中奖概率，不显示库存数量或有货/没货标签。
- 每种奖品配置名称、图片、后台库存、单份价值与固定中奖概率，精度 0.01%，每项大于 0，总和不超过 100%，剩余为谢谢参与。库存可独立于参与名额备货，单项上限 100000；预算覆盖全部奖品总价值，发布后冻结配置。
- 兑换码和链接增加平台、使用说明、有效期；兑换码可配置公开的 HTTPS 使用入口。数字库存逐份导入，发布前须备齐。
- 抽奖、积分扣减、奖品库存扣减、数字库存分配与订单在同一事务；重复参与不再扣分或更换奖品。
- 数字库存以独立密钥 AES-GCM 加密，重复凭证拒绝导入。活动、中奖公示、管理列表、审计均不返回凭证明文；仅订单所属用户可通过独立接口查看自己的兑换凭证。
- 实物保持填写地址、后台发货、确认收货。数字奖品直接发放至我的奖品，支持复制和打开外部 HTTPS 兑换入口，显示目标域名；不模拟外部平台核销。
- 库存导入仅限草稿，活动发布须具备足量库存。原有线上活动不会自动替换奖品或新增示例活动。
- 返回使用已有历史策略；切换活动页签替换当前地址，避免积分页与活动页循环。

## 交付边界

外部兑换使用运营提供的真实库存及入口；不连接或冒充第三方发卡、充值、核销 API。不在生产消耗积分或制造中奖记录。iOS 验收不能代替用户真机安装。

## 运维约束

`RewardsEncryptionKey` 使用独立的 32 字节 base64 密钥，保存在营销服务运行配置，备份必须同时保留数据库和密钥。已有库存后不能直接替换密钥，否则旧凭证不能解密；轮换必须另作解密再加密迁移。生产不导入示例库存。

旧服务不能理解多奖项及数字履约，新增多奖项活动后不允许直接回退旧服务继续运营；先评估活动、已发订单与凭证读取能力。增量字段和表不反向删除，不删除持久密钥。
