# 积分活动参与与示例数据

## 规则

转盘与大奖池统一从积分页面进入，消耗当前活动配置的积分。积分兑换继续提供确定权益；活动不收现金、不按商品价值换算积分费用，不等待参与积分覆盖成本。平台独立承担奖品预算；功德值不参与支付、概率加权或活动增长。

保留一期一人一码、截止开奖、等概率无放回、进度、公告审计、领奖和实物履约。参与成功后，无论是否中奖均不退积分；后台不允许取消已有参与的活动。

## 实现

- `pointsCost` 为正整数、独立配置，发布后冻结。H5/iOS 显示余额、消耗和扣除后余额，明确确认再提交 `expectedPoints`；旧客户端无确认参数被拒绝，避免意外扣分。
- 现有积分账户行锁 + 唯一流水键 + 活动参与唯一键，余额、流水、参与码、人数和即时奖品订单一起提交；余额不足、随机源/审计故障全部回滚。同一期重试返回原记录，跨活动不能超扣。
- 营销库与支付库当前同机，使用跨 schema 的单一 InnoDB 事务；营销账号仅增加积分账户 SELECT/UPDATE(balance)、积分流水 SELECT/INSERT。不复制积分账户，不改现金或功德。拆库到不同服务器前需重新设计事务方案。
- H5 积分页集中展示转盘、奖池、参与记录、我的奖品和开放活动；移除首页及个人页直接活动入口。iOS 同步入口、扣分确认及流水标签。统一后台新增参与积分配置和列表详情。
- 增量迁移给旧记录补零，历史免费参与不追扣，历史草稿必须补正积分才能发布。

## 示例

通过后端 `scripts/seed-reward-examples.py` 创建两项可复用草稿：平安香囊转盘（10 积分，20 份，200 名额）和天然香珠手串奖池（20 积分，1 份，100 名额）。开始为创建时，截止为 14 天后。预算、数量和积分均可在发布前修改。

脚本默认只建草稿；已有同名活动复用，不自动续期、补库存或覆盖规则。发布使用 `--publish`，须先确认平台实际提供奖品。不给账号灌入积分，不虚构参与人、中奖码或发货记录。
