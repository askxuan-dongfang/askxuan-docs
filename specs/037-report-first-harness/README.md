# 专题报告优先与 Harness 生成

> **Status**: ⏳ In progress · **Priority**: Medium · **Created**: 2026-09-29


状态：H5 与后端已发布，四类真实报告、关联追问和生产页面验收通过。原生 iOS 对齐、构建和模拟器验收已完成；竞品完整对标仍待后续工作，故整项规格继续保持 in-progress。

## 目标

保留专题、问 AI、我的报告三页。把默认旅程改为选专题、填资料、阅读图文报告、关联追问，避免 18 项底层技能与专题重复展示。直接问 AI 与历史会话继续存在。

## 设计

- 12 个专题：原有八字、紫微、合盘、风水、六爻、奇门、塔罗，增加姓名、解梦、择日、每日运势、面相手相。
- 报告经 Eino Harness 生成。必要计算先行；智能体可读取已计算依据并按需调用审核工具。四次模型、工具预算等上限继承执行器；整份报告外层工具调用另限 6 次（待发布复合工具的内部请求另有范围限制）。
- 原始计算证据存入私有 document_json；前端只得到解锁后的标准图表块。用户文字不能指定组件或执行代码。
- 八字必算四柱和大运；合盘分别计算双方八字并标注主体；择日对照最多 3 个明确日期。
- 图表包括四柱、藏干表、等权五行数量、大运流年、十二宫、六爻、奇门九宫、塔罗牌阵和黄历。模型不能生成伪造评分。
- 报告首次打开只返回摘要；既有支付及归属校验保护正文、图表和追问。历史纯文本报告保持兼容。
- 12 份原创示例使用合成测试资料。姓名、梦境、空间建议属于文字与对照表，不冒充算法排盘。面相手相仅解释可见特征和术语，需可用视觉模型。

## UI 决策

| Before | After | Why |
| --- | --- | --- |
| 技能库与专题入口重复 | 专题优先，技能由后台调度 | 用户按目的进入 |
| 报告主要长文本 | 计算图表、章节、明细表、关联追问 | 依据与解释可以对照 |
| 聊天首屏承担全部任务 | 直接提问保留为独立页 | 同时满足专题与即时问题 |
| 表格始终铺开 | 阅读时展开明细，打印时完整展开 | 控制手机长度，保留导出完整性 |
